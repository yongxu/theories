For the section on checks from scratch, added later the same day, the script reads by pattern the scratch Lean filed as text in this study, and the declaration lines of the tracked Lean files that contain the names those checks use. The rows say which, since two places can share a row; the readers' own names for the place are kept under it. Both outputs are made by it and never edited by hand. Whoever lands a place-by-place read adds its returns and runs the script in that landing; a listing that is not made again after the next read is worse than none.

## What it is not

- **Not checked.** Every field is one AI reader's return, read by no second reader. The notes of the three reads were each checked against the readers' full reports and mended; these returns are the readers' short structured answers, the least checked text of each read, and a checker found the writer misquoting from them. So every return carries the path of its read's note and of the reader's report. Where a return and the report differ, the report stands; where the note mended something, the note stands.
- **Not the atlas, not a replacement for it, and not the data structure of the map.** The atlas lists dynamics and the links the Lean proves between them. This lists places and what readers said of them. Nothing here is a link. The open item on who holds the atlas and what becomes of the second store (the board's line 0, e) stays open, and the rows that hold them are not answered by this.
- **Not a count to move.** The figures above are a description in this note; the files hold no totals and nothing that adds up per place.
- **Not complete.** A blank means a place was not in that read. Until 22 November the listing held 158 places, 104 of them modules of the package; since then every module of the package has a page, and the modules no earlier read had named are read only by the whole read's fixed questions.

## What it is for

To find, for a place, what has already been read of it before anyone reads it again or proposes something about it; and to see, across places, which have been set against which question. That is all it can bear.

What the place might carry later, if this ever grows toward the map's own structure, is not readings but what was drawn: which statement is a case of which, and how that was checked. That is the coordinating session's thought and is not done here. The next section lists something else that a script can read off a file: checks that two statements are the same up to unfolding.

## Same statement, up to unfolding: checks filed in scratch (added 21 November, later the same day)

A scratch module can hold a check of the form `theorem X : @A = @B := rfl`. Where Lean accepts it, the types of `A` and `B` (their statements) are definitionally equal: they reduce to the same term by unfolding definitions and Lean's other reductions, with binder names and which arguments are implicit ignored and proofs inside them identified. That is what "the same up to unfolding" means on every line here. The `rfl` itself adds nothing, since two proofs of one proposition are equal. It shows nothing about how either was proved, and not that one is a case of the other. Only the two checks of the renewal bridge write a universe (`.{u}`) on both sides; in the others the universe levels are left to Lean, and the data records which were written. The reader who gave this wording did not check whether Lean's reading of `=` could have put in a coercion, and called that remote for proofs of propositions. A first form of this section, not landed, called the scratch statement "a case" of the older one; the check does not show that, and the word is not used.

The script (function `same_statements`) sweeps every tracked file named `Scratch*.lean.txt` under this row's study folder, twelve at this run, with comments blanked, and finds eight such checks: seven in the scratch of 21 November and one in the scratch of 17 November. The first form listed seven, from the writer's memory of them; the sweep found the eighth. For each check the listing carries:

- **The two statements, by full name, each with the file and line that declares it.** The file is found by search and not typed: first the check's own file, under the namespaces enclosing the check, from the innermost out; then every tracked Lean file with copies left out, and every tracked file named `Scratch*.lean.txt` in this study, for a theorem whose full name is the name written or ends with it at a dot. Where one file fits, that is the side's file. Where none or more than one fits, the line says "place not resolved" and names the files that fit. At this run each of the sixteen sides has one file, and one reader, reading the namespaces and `open` lines at each check, found that Lean resolves each name as written to the declaration listed.
- **The build log filed beside the module that holds the check, and what it says.** At this run the logs of the four modules of 21 November that hold a check each say exit 0 and an empty axiom report. The log of 17 November has an empty axiom report and no exit line, and the line says "no exit line found".
- **Whether a theorem of the left statement's bare name is declared in the package** (`becoming/Becoming`), searched at each run and written as found. At this run none is, for the seven of 21 November. For the check of 17 November the name is `two_units_iff`, and what is found is the package's own theorem of that name, which is the other side of that check and not the scratch statement; the line says so.

Where the right-hand statement is resolved, the line stands under the place of the file that declares it: at this run `WayOfUnits`, `TurningInTime`, `RenewalConfigurations` and `ScratchMixedWay`. A check whose right side were not resolved would stand in the section's table and under no place; at this run there is none.

What this section is not:

- **Not a build.** The script runs no Lean. The log is the one that was filed with the text; nothing here checks that the text filed, or the file named for the other side, is the text that was built. One of the two readers compared the six scratch texts with the copies in the build trees the logs name and found them the same byte for byte on 21 November; that does not show they were the same when built.
- **Not in the package, and not a link of the atlas.** Every left-hand statement is in scratch text outside the package.
- **Not Lean's own reading of names.** Which file declares a statement is read off the lines `namespace`, `section`, `mutual`, `end` and `theorem` or `lemma`, with comments blanked. `open` lines, imports and the order of declarations are not read. A statement declared in another way (a `def`, an `abbrev`) is not found, and a comment mark inside a string, or an `end A.B` closing two namespaces opened one by one, would be misread; one reader looked for these in the sixteen files read at this run and found none.
- **Not every check.** Only the form above, ending its line with `rfl`, is matched. A sameness shown another way (an `example`, an `Iff.rfl`, a `by rfl`, a check in a file not named `Scratch…`) is not listed, and its absence here says nothing. One reader searched this study's filed text for others and found none beyond the eight.
- **Not joined to the table's rows.** `ScratchMixedWay` is a place here by its file name, beside the table's row "The scratch Lean of 17 November …"; `RenewalConfigurations` is a place beside `conditional/renewal`. The script has no hand table to join them, by the coordinating session's third condition below, and a reader has to.

For what each scratch statement was proved from, and who read it, see the note of the scratch folder that holds the check, which every line links; at this run that is also the folder of the left-hand statement. The two readers of this section did not read those notes.
