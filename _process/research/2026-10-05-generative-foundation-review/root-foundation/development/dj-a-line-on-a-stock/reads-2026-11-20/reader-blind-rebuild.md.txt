# A blind rebuild of the regions computation

## Part 1. My own program and its numbers, written before the writer's programs or results were opened

`rebuild.py` (sha256 `a3a92e7c…66ba76` as first run) was written from "The question" in `FROZEN-REGIONS.md` and the particulars in my brief. It took 0.03 s for (a) and 4.4 s for the sweep.

**How I read the definitions.** A configuration is (f, o, rule in force, level). At a step a unit whose need is at most the level leaves its kids under the rule in force; every unit present takes its use, met or not; z = max(0, level − taken); the next level is z + min(z, c − z); the move becomes the rule in force at the next configuration. So the two next configurations differ only in their rule. A configuration is in a region only if the guard holds at it. "One rule held" = the same move at every step from here (the rule already in force at the start is what the configuration has). "Threshold" = rule 1 exactly where f ≥ t, for every t from 0 up (t = 0 and t above every f are the two constants, so the classes are nested: K ⊆ one rule ⊆ threshold ⊆ function of f ⊆ function of (f, level) ⊆ Kp). R is asked per start: one function whose course from that start is kept.

**Methods, none a depth-first search over partial choices.** K and Kp: greatest fixed points by removal along predecessors, on everything reachable from the starts through configurations within the guard (finite here: needs and uses are at least 1, so a configuration that takes its whole level is followed by level 0, where no need is met). For readings of f, method B: the set W(x) of all functions f → move whose course from x is kept, held as a bitmask over all 2^(fmax+1) functions and computed as a greatest fixed point, W(x) = (W(next₀ x) ∩ {g(f_x) = 0}) ∪ (W(next₁ x) ∩ {g(f_x) = 1}); "one rule" and "threshold" are particular members. Method S: plain simulation of the two constants and each threshold until the guard fails or a configuration repeats. Method A, for any reading: C = what is reachable from the start inside Kp; enumerate every assignment of moves to the readings that two or more configurations of C share, and for each take the fixed point "kept by some sequence" in the graph so restricted (readings met once constrain nothing). Method X, on every 40th model: all functions over all readings in C, each simulated. B, S and A agreed on every one of the 912,384 starts (0 mismatches); X agreed with A on 5,450 starts for each of the two readings (0 disagreements). A never had to enumerate more than 5 readings.

### Every difference, with its cause

1. **The "none" count of the sweep (402,866 against my 644,786).** Cause: `regions.py` line 229, `if not g(s): continue`: the writer tallies only starts at which the guard holds (670,464); I tallied all 912,384 starts and put the 241,920 at which nothing goes on under "none". 644,786 − 402,866 = 241,920 = 912,384 − 670,464. Neither is wrong; the writer's heading says "670,464 configurations in which something goes on". Example of a start in my count and not the writer's: c = 8, needs (1, 1), start (0, 1, rule 0, level 0).
2. **Where "the rule becomes 0" is looked for.** `regions_2.py` line 67 looks for the first configuration with rule 0 in force only among configurations within the guard; mine also looks at the configuration at which the guard fails. No start in the family tells the two apart (in all 96 the first rule-0 configuration is within the guard), so the six numbers agree.

There is no other difference. In particular the writer's `kept_by_reading` (depth-first over partial choices, with "in K" and "back on the path" as the two ways to succeed) gives, on every configuration compared, what a greatest fixed point over sets of functions (B), an enumeration over the shared readings with a restricted "some sequence" fixed point (A), and on a sample a plain enumeration of all functions (X) give.
