## Module 1: ScratchKeepableStep.lean

### 1. `keepable_step_iff`: as asked (no finding)

`theorem keepable_step_iff {P : Process S A} {g : S → Prop} {s : S} : Keepable P g s ↔ g s ∧ ∃ a t, P.step s a t ∧ Keepable P g t`

- **In plain words:** for every process, guard and configuration, with no premise: some run from `s` stays within `g` exactly when `g` holds at `s` and some step from `s` leads to a configuration from which some run stays within `g`.
- `Keepable` (JointKeeping 91) is `∃ r : Run P, r.state 0 = s ∧ ∀ n, g (r.state n)`.
- **Against what was asked:** it is the same statement. The forward proof uses `r.onward 1` with `held (1 + n)`. The backward proof uses `Run.cons` (Horizon 93). The docstring is right, including "the twin of `kernel_step_iff`" (Viability 98).

### 2. `not_keepable_step` / `not_keepable_run`: as asked; the premise could be local (LESSER)

`theorem not_keepable_step {P} {g} (closed : ∀ s a t, P.step s a t → ¬ g s → ¬ g t) {s a t} (lost : ¬ Keepable P g s) (step : P.step s a t) : ¬ Keepable P g t`

`theorem not_keepable_run {P} {g} (closed : …) (r : Run P) (lost : ¬ Keepable P g (r.state 0)) : ∀ n, ¬ Keepable P g (r.state n)`

- **In plain words:** if every step from outside `g` stays outside `g`, then a step from a configuration that `g` is not keepable from leads to one it is not keepable from. Along a run whose start is not keepable, no configuration is keepable. These are the statements as asked, with no decision of `g` used.
- **LESSER:**
  - The step form uses `closed` only at the one step it is given. Argued, not built: if `t` is keepable, then `g t` holds, so `¬ g s` is false by the local premise, so `g s` holds, and `keepable_step_iff` makes `s` keepable.
  - A step form with the local premise `(closed : ¬ g s → ¬ g t)` is strictly stronger. It would put the October `dead_stays_dead` (which is itself local) straight in as the premise.
  - Suggested: `theorem not_keepable_step {P g s a t} (step : P.step s a t) (closed : ¬ g s → ¬ g t) (lost : ¬ Keepable P g s) : ¬ Keepable P g t`, with the run form keeping the global `closed`.
  - This is optional. The worded premise is what was asked.

## Module 2: ScratchUnitsTurn.lean

### 7. `units_turn_iff`: U2 as corrected, with `T` given (no finding)

`theorem units_turn_iff {m n hi y T : Nat} {w : List U} {x : Nat} (sm : ∀ u, S u → need u = m) (stay : Stays S need kids n w) (needs : 0 < n) (order : n ≤ m) (nothing : FromNothing giving) (high : x ≤ hi) (keeps : Keeps giving (taken use (strip S w)) hi) (before : ∀ j < T, m ≤ X j) (belowT : X T < m) (short : Short giving H_T y) (meets : Meets giving H_T y hi) (within : n ≤ H_T + y) : «不穷» (net need kids giving use) «一» (w, x) ↔ n ≤ X T ∧ H_T + y ≤ X (T+1)`

Here `X := wasLevel kids use giving w x`, `H_T := taken use (strip S (generation kids T w))`, and `{S} [DecidablePred S]` comes from the section.

**Premise by premise:**
- The growers `S` are decided, and each needs `m`.
- Every unit not of `S` in every generation of `w` (the course as it was: all kids at every step) has `kids u = [u]` and needs `n` (`Stays`, line 489).
- `0 < n ≤ m`, nothing is given from nothing, and the start is at most `hi`.
- The step under what `w`'s stayers take keeps the level within `hi`.
- `T` is the first step at which the course as it was is below `m`.
- At that `T`: `Short`, `Meets`, and `n ≤ H_T + y`.

**Conclusion:** the net never ends exactly where `n ≤ X_T` and `H_T + y ≤ X_{T+1}`.

**Against U2 as corrected** (u2-against-rows: `S` decidable; `T` the first `j` with `X_j < m`; the premises at `T` only; `R_T ≠ []` redundant; the right side `n ≤ X_T ∧ H_T + y_T ≤ X_{T+1}`), the Lean says the same:
- **`T`:** it is fixed by `before` and `belowT`, not by `Nat.find`.
- **`R_T ≠ []`:** it is dropped and derived in the proof (`draw_pos`, from `short` and `0 < n ≤ H_T + y`).
- **Growers:** the Lean asks nothing of what a grower leaves, so it is more general than W2's "grower leaves growers and stayers". Every kid that is not of `S` is held to `Stays` because it is in some generation.

There is nothing less and nothing other.

### 11. `one_need_ends`: narrower than its docstring says (LESSER)

`theorem one_need_ends {m} {w} {x} (one : ∀ k u, u ∈ generation kids k w → need u = m) (comes : ∃ N, X N < m) : ¬ «不穷» (net …) «一» (w, x)`

- **What its docstring says:** "This is the case `units_turn_iff` does not reach: a turn that leaves no unit not of `S`." The module header (line 34) says the same.
- **Why that is too broad:** `one` asks every unit of every generation, including those after the turn, to need `m`. A turn that leaves no stayer at `T` can still have growers whose kids in generation `T + 1` of the course as it was are stayers. There the net also ends: at `T`, no grower's need is met and there is no other unit. But `one` fails.
- **What the theorem does cover:** the two uses (equal pairs, and `n = m`). It is not the whole of the case the turn law does not reach.
- **Suggested words:** "the case where every unit of every generation needs the same `m`; it covers the cases below where the turn law does not reach."
- **Or, as a statement covering the whole complement** (argued, not built): `theorem no_stayer_ends (sm) (stay) (order) (before : ∀ j < T, m ≤ X j) (belowT : X T < m) (none : strip S (generation kids T w) = []) : ¬ «不穷» (net …) «一» (w, x)`. The proof is `met_before` up to `T` with need at most `m` (from `sm` and `stay`; `Stays` gives `need u = n ≤ m` for the units not of `S`), and then no unit is met at `T`.
