DECISIONS THE DESIGN LEFT TO ME

- **When the check passes with no print.** It passes, with a `note` and `bound: None`, only when all three hold:
  - `INDEX.json` is absent from the working tree;
  - `INDEX.json` is absent from the merge base with `base` (`files_at(base_commit(base))`);
  - no file at all lies under the print's directory.

  An index the landing deletes fails. Module files without their index also fail, because I read "no index at all" as "no print at all". An index that is present, whether it was there before or the landing adds it, always goes to `status(ROOT)`. If the module or its `status` is absent at that point, the check fails with the run message.
- **What counts as bound.** The check fails exactly when `bound` is false. `problems` are listed as errors only when not bound; when bound they are reported but do not fail. An exception from `status()` is caught and reported as a failure of the check, not a crash.
- **The escape covers every failure** of the check, including a missing index or tool, not only "not bound". The pass key (`environment()`) does not include the escape, which is the same as `GATE_BOARD_REWRITE`. So a pass won by the escape can be reused on the same tree, or across a diff that reaches nothing the check reads.
- **Output key names.** The escape's reason is `accepted_reason`, the board's equivalent is `accepted_rewrite`, and `would_fail` works as the board's does. The reason reaches the check's JSON output, which goes to its gate log, the way the board's does. `run()`'s summary shows only the status, as it does for the board.
- **The receipt is not listed separately** in the check's reads, because `LEAN/**` covers it. The tool path also selects every check through CODE, as the existing rule does.
