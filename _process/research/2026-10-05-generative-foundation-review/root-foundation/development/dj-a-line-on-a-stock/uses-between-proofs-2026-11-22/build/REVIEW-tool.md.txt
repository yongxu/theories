Review of `/Users/ren/tmp/dj/wt-layer/tools/research/proof_uses.py` and `tools/research/tests/test_proof_uses.py`

I found one defect that writes a wrong print (MUST 1) and one hole where a stale print passes as bound (MUST 2). The rest are LESSER. All 24 tests pass (`python3 -B -m unittest tools.research.tests.test_proof_uses`, 0.078 s). I ran no Lean, render or gate and changed no file.

**Findings**

1. **MUST: a module that silently loses its rows still gives a bound print.** proof_uses.py, lines 692–696.
   - The Lean side filters modules by `receiptModules.contains (toString m)`. If that string test misses a module (a `toString` that differs from the receipt's name, or a future edit), its theorems drop out inside Lean.
   - The COUNT line still agrees with the rows printed, and `parse_output` gives that module an empty list. The only guard is "no row at all".
   - The receipt already holds a floor for each module. On batch29's rows, every `Becoming.*` module has at least as many rows as the receipt's `modules[].theorems`. The three outside modules are the only ones with theorems and no rows (35, 23 and 16), because the old printer skipped them.
   - Fix, after `parse_output`:
     ```python
     short = sorted(m['module'] for m in receipt.get('modules', []) if isinstance(m, dict)
                    and m.get('module') in by_module and len(by_module[m['module']]) < (m.get('theorems') or 0))
     if short:
         raise Refused(f'the printer gave fewer rows than the receipt counts theorems for {len(short)} module(s), e.g. {short[:3]}')
     ```
     This also turns the untested "private theorems are kept / the outside modules have rows" into something the first real run can fail.

2. **MUST: `bound` ignores the toolchain.** proof_uses.py, line 479.
   - A toolchain bump with no `.lean` change gives a new receipt with the same `source_sha256`, so `core_sources_sha256` is unchanged and the print stays bound. Yet the proof terms are those of the old Lean.
   - The gate check is selected (lean-toolchain is under `LEAN/**`) and passes. The index records `toolchain` for exactly this case.
   - Fix: `out['bound'] = out['sources_bound'] and out['printer_bound'] and out['toolchain_agrees']`, plus a problem sentence: `'the print was made with toolchain {index toolchain}; the core receipt is of {receipt toolchain}'`.
   - Update `test_the_toolchain_is_told_beside_bound` to expect `bound` False.
   - This departs from A7's letter ("sources and printer"). Its reason is the reason A4 records the toolchain.

3. **LESSER: the gate passes a damaged print that `--check` and the atlas reader refuse.**
   - `damage` does not enter `bound`, and `gate.proof_uses_check` reads only `bound`. So a deleted or cut module file passes the gate.
   - Meanwhile `--check` exits 1, and `atlas._proof_uses` returns "the index names the module m and it has no file".
   - Fix in gate.py `proof_uses_check`, after reading `found`: `errors += [f'the print\'s files: {d}' for d in found.get('damage') or []]`. Leave `bound` as it is.

4. **LESSER: a Lean panic is not refused.** proof_uses.py, line 286.
   - `getElem!` (`inReceipt[idx.toNat]!`, `mods[...]!`) prints `PANIC at …` and carries on with a default value, and the exit code stays 0. The line goes into `notes`, and the run writes.
   - Fix: `errors = [n for n in notes if re.search(r'\berror:|PANIC', n)]`.

5. **LESSER: the index's words say slightly more or less than the printer does.** ABOUT, lines 96–98 and 101–102; the same in the module docstring.
   - "Definitions are not followed" contradicts the earlier clause: matchers are definitions under the theorem's name, and they are followed. Should read: "No other definition is followed, so a use that passes through a definition's body does not show."
   - "(equation lemmas, injectivity lemmas, abstracted proofs under a definition)" is narrower than `skipLast`/`isInternal`. These also skip `_auxLemma.N`, and `thm._proof_N` / `thm._simp_N` that Lean's aux-lemma cache reuses in another theorem. Add: "and any name with a part beginning `_`, such as an abstracted proof under another theorem that Lean reuses."
   - "what a used theorem's own proof uses is on that theorem's line" holds only for used theorems that have a line. Add: "where it has one".
