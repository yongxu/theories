1. MUST: the design's own way of telling that P1 is behind would break the render's binding to its inputs. Better: compare against the core receipt, which is already an input. P4 says the render "hashes each module's tracked source". But `research.py` ties every render to a list of files it read (`input_snapshot`, tools/research/research.py:41-67), and the atlas adds to that list through `atlas.inputs()` (research.py:52; atlas.py:1792-1800). No `.lean` file is on the list. Hashing 412 sources at render would make the pages depend on files outside it. Adding them would make every Lean edit change the atlas inputs, and `test_atlas.py::test_inputs_are_the_curated_files` (422-425) pins the exact list.
   - Nothing new is needed. The core receipt `becoming-verification.json` already holds `source_sha256` for all 412 modules. It is already an input (`atlas_index.inputs()`, atlas_index.py:133-136), and the validator already reads it (`Repository.declared`, atlas.py:263-267).
   - `gate.receipt_check` (gate.py:895-922) already fails a landing whose receipt does not match the current bytes. So on any gated tree, comparing P1's header with the receipt gives the same answer as hashing the sources.
   - There is a precedent to copy. `shared_laws.py` stores `core_sources_sha256 = sha256(json.dumps(receipt['source_sha256'], sort_keys=True))` (shared_laws.py:264-266, 387). `registry.shared_laws_status` (registry.py:901-925, line 918) shows "current" and is not enforced. P4 can do the same per module.

2. MUST: P1 must enter the render through `atlas.inputs()`, and only when the file exists, the way the crosswalk checks do (atlas.py:1796-1797). Otherwise `test_inputs_are_the_curated_files` fails, because its fixture has no P1.
   - Committing P1 without re-rendering breaks every later check. Plain `research.py check` reports "generated view differs" for any page that differs (research.py:471-477). A landing that commits P1 without rendering would stop the next session's gate. That goes against the design's own rule "Stop another session's landing".
   - So P2 must be told: run P2, then render, in the same landing.

3. MUST (outside my brief, but it bears on design point 4): the printer misses some declarations the atlas lists. `AllProofHeads.lean` keeps only modules whose name starts with `Becoming` (lines 80 and 87 of AllProofHeads.lean.txt). The receipt's package also has `RelationalRenewal`, `GenerativeCore` and `InquirySufficiency`; 74 of its theorems are not in the list.
   - 11 declarations listed under `loss-of-renewal-for-good` and `becoming-return-grades` (for example `RelationalRenewal.Law.no_return_below_support`) are in the receipt but not in all-proof-heads.jsonl. They would silently get no link, and uses into those modules are dropped too.
   - P1's wording "declared in a module of the package" says more than the printer does. Either print every module in the receipt's `core_closure`, or state the limit.
   - Name matching should use the validator's rule exactly: the name as written, else `Becoming.` + name (atlas.py:267). atlas_index.py:206 does the same.

4. LESSER: the size is understated. P1 as designed (name, module, uses; compact JSON, CJK unescaped) is about 3.1 MB for 20,567 lines, not "a megabyte or two". The smaller option in attack point 1 (only theorems reached from listed theorems through unlisted ones) is 6,780 lines and about 0.8 MB, measured on the 22 November list. `module` could also be dropped from each line, because the receipt's `modules[].declarations` gives every declaration's module.
