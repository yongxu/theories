## 3. The family form

**What discharges each clause**

| Clause | Config, `Stays` (statement path) | Config, `Viable` (`viable_or_lost`, copy `lost_not_viable`) | Reading, `K n c = KeptFor … n (decode c)` |
|---|---|---|---|
| `zero` (disjoint and either) | `fun _ => id` | `fun _ => id` | `fun _ => id` (`KeptFor 0` is `codeGuard` by definition) |
| `below` | `fun _ _ => id` | `fun _ _ => id` (`Viable (n+1)` unfolds to `stayStep … (Viable n)`) | `kept_below`, no premise |
| `above` | `fun _ _ => id` | `fun _ _ => id` | `kept_above updates` |
| `down` | `same.symm ▸ h` | `same.symm ▸ h` | `fun _ _ _ sub => KeptFor.mono sub` |

**Where `updates` enters:** in exactly three places.

- `above` (`kept_above`);
- `outcomes` (`seen_outcomes`: one exact code per listed value, through `listed_partners`);
- the landed kept bound (`coded_kept_iff_closed`).

It does not enter `zero`, `below`, `down`, or anything on the never-both side. `someValues` enters only `seen_outcomes`.

**Is it a real generality?** Only the reading uses `stage` other than the iterate, and only the reading uses `under` other than `Eq`.

- `Viable` is no second family: its clauses are all definitional, and `iter_iff_viable` is `iter_iff_stages … Iff.rfl Iff.rfl`. It is the iterate under another name.
- So the family form and `under` are one statement with two parameters that one case needs.
- `stage := KeptFor` is bought to get `down` for free from `KeptFor.mono`. With `stage := Stays` on codes, `down` along inclusion would need an induction of its own.

**Could the reading be a case without `under`?** Not with these premises. With `under := Eq`, `outcomes` would need a list holding every code `d` with `seenNext c a d`, with `seenNext` decided on it.

- Two codes can name one class. So every code naming a seen class must be listed, and `∃ o, ∀ s, decode d s ↔ Seen …` must be decided for each one. That is a decision about classes, which the premises do not give and the level reading (values in `Nat`) would not meet from `[0, 1, 2]`.
- Weakening `someValues` back to "all values listed" (the first module's `everyValue`) still leaves `under` as "names the same class": an equivalence, not `Eq`.
- Taking classes themselves as positions would need equality of predicates (`propext`/`funext`).

So `under` is the price of the reading. Inclusion is forced by the weakened `someValues`.

**What `example : @copy = @GuardHorizon.name := rfl` checks.** Both sides are proofs, so by proof irrelevance they are definitionally equal as soon as their types unify. The check therefore says only that the two statements are definitionally equal after unfolding. It would **not** catch:

- (a) a copy with a proof of its own, such as a recursion instead of a call, so it says nothing about whether a copy is a call;
- (b) binder kinds, explicit against implicit, which definitional equality ignores;
- (c) a copy less universe-polymorphic than the landed one, because universe metavariables on the landed side can be set to 0;
- (d) a statement stated through other definitions that unfold to the same thing (this one is intended);
- (e) the docstrings.

It would catch argument order and real differences in the statements.
