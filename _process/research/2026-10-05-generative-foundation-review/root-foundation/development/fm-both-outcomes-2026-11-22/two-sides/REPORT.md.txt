  ∀ s, decode d s ↔ B s

  ∃ s, decode c s ∧ ¬ guard s

def lostReadingStep (P : Process S A) (sense : S → A → S → O) (guard : S → Prop)

## 3. Choice of loss step and changes to premises

I used the disjunction in the brief for each move. An unusable move supplies its own reply. The other reply exhibits a value and an exact code for its seen class. This form lets `gather_listed` establish commutation before any usability decision is available. Pointwise `Names` supplies both inclusions where they are needed. Part A transfers keeping from the seen class to the code. Part C transfers it from the code to the seen class.

An empty class has no `Outside` witness. With a move available it is kept at every horizon by `keptFor_empty`, so same-horizon exclusion applies. If the move type is empty, the universal reply holds vacuously at the first successor horizon, and successor keeping would require a move.

Part B drops all listing and update premises. The finite-horizon split in Part C drops the code list. It asks for usability decisions only on guarded codes, and for updates and a list of values only after a usable move from a guarded code. That list may depend on the code and move and must cover every value of `O`. No premise was added and no requested conclusion was weakened.

Both starts have level two, one in each lane. With `noneRead`, every move returns the same observation `()`. Choosing `true` and then `false` keeps both lanes above zero for two steps. In any three moves, one lane experiences at least two decreases. The direct loss proof follows that lane through the three exact successor codes to a configuration at zero.
