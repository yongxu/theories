# Design B: a web kept by goings-on, with a finite source and a cost (holding, or changing)

*AI-written (Claude Opus 5.5, designer B, angle "things kept by goings-on"), 21 November 2026, about 23:45 by the machine's clock. Python only, twelve runs, each under 60 s but one (section 6); no Lean, no build, no test, no gate; nothing in git touched. Unit, ground, act, formation, standing, closing are working names.*

## 1. The design in ten lines

1. A configuration is a count of tokens of finitely many kinds, n : K → ℕ, at most the caps C (the finite source).
2. A law gives each kind k a recipe R k : K → ℕ (acts of each kind needed to form one token of k) and each kind j a capacity c j (acts a token of j gives in a step).
3. A step: the tokens act once and are gone; the next configuration is the births, any b ≤ C with Σ_k b k · R k j ≤ c j · n j for every j. An act serves one forming, so what a token gives to forming another kind it does not give to its own (keeping costs the keeper).
4. A formation D ⊆ K goes on while some kind of D has a token; V_D is the set of configurations from which some course keeps it for ever (a choice among moves).
5. A way of selecting picks a move at each step. It is *closing* when it forms no kind absent from the configuration: what can be formed is set again from what it formed last (every selection that allots by share is closing).
6. Registered: what is present, nothing more (no reading; R6 is left out).
7. A *standing population* is x ≤ C with x → x a move and some kind of D in x.
8. Main law: the moves are closed under pointwise min always, under + where no cap binds, under max where support is free; the fold of a cycle by such an operation (for +, of a stretch whose end is at or above its start) is a standing population.
9. Hence exactly one of: (i) no course keeps D; (ii) a standing population exists, and a closing course keeps D from n exactly when a closing course from n reaches a configuration at or above one; (iii) some course keeps D but none holds any form: in every course that keeps D each kind of D is absent at infinitely many steps, and every closing course, from every start, passes a step after which no course keeps D.
10. Case (iii) needs both a finite source and a cost: with no caps, or with support free, every law that keeps D at all has a standing population. Built: two partner kinds on a ground that can carry one of them a step; holding both gives the ground's own renewing act away, holding one loses the other for good, and the formation goes on only by the partners taking turns.

## 2. Definitions

```
variable {K : Type} [Fintype K] [DecidableEq K]

structure Law (K) where
  R : K → K → ℕ      -- R k j : acts of kind j needed to form one token of kind k
  c : K → ℕ          -- acts one token of kind j gives in a step
  C : K → ℕ          -- most tokens of kind k one step forms (the finite source)

abbrev Config (K) := K → ℕ

-- costly support, with caps (the model)
def Move (W : Law K) (n b : Config K) : Prop :=
  (∀ k, b k ≤ W.C k) ∧ ∀ j, (∑ k, b k * W.R k j) ≤ W.c j * n j
-- the two variants, each taking one part out
def MoveUncapped (W) (n b) : Prop := ∀ j, (∑ k, b k * W.R k j) ≤ W.c j * n j
def MoveFree (W) (n b) : Prop :=          -- a supporter's act serves any number of formings
  (∀ k, b k ≤ W.C k) ∧ ∀ k, 0 < b k → ∀ j, W.R k j ≤ W.c j * n j

def Live (D : K → Prop) (n : Config K) : Prop := ∃ k, D k ∧ 0 < n k
def Course (Step : Config K → Config K → Prop) (s : ℕ → Config K) : Prop := ∀ t, Step (s t) (s (t+1))
def Keeps (Step) (D) (n) : Prop := ∃ s, s 0 = n ∧ Course Step s ∧ ∀ t, Live D (s t)   -- n ∈ V_D
def Standing (Step) (D) (x) : Prop := Step x x ∧ Live D x
def Closing (n b : Config K) : Prop := ∀ k, 0 < b k → 0 < n k
def ClosingCourse (W) (s) : Prop := Course (Move W) s ∧ ∀ t, Closing (s t) (s (t+1))
def ClosedUnder (Step) (op : Config K → Config K → Config K) : Prop :=
  ∀ n b n' b', Step n b → Step n' b' → Step (op n n') (op b b')
def DownClosed (Step) : Prop := ∀ n b b', Step n b → b' ≤ b → Step n b'
```

The cases: (i) `¬ ∃ n, Keeps (Move W) D n`; (ii) `∃ x, Standing (Move W) D x`; (iii) `(∃ n, Keeps (Move W) D n) ∧ ¬ ∃ x, Standing (Move W) D x`. As a `Process` of the package: configurations `Config K`, moves the births `b`, step `Move W n b ∧ next = b`; `Keeps` would then be `Keepable … (Live D)` and V_D its kernel of choice. That bridge is named, not written.

New definitions: `Law`, `Move` (with two variants), `Live`, `Keeps`, `Standing`, `Closing`, `ClosedUnder`; `Course` and `DownClosed` are generic.

## 3. The main statement

**Theorem B.** Premises, all of them: `K` finite with decidable equality; `W : Law K` with values in ℕ; `D : K → Prop`. (No premise on the level's fall, the giving, a rise of use, a lock, a turn or an end.)

- **(B1) The lattice of moves.** `Move W` is `DownClosed` and `ClosedUnder` pointwise `min`. `MoveUncapped W` is `DownClosed` and `ClosedUnder` `min` and `+`. `MoveFree W` is `DownClosed` and `ClosedUnder` `min` and `max`. (`Move W` is in general closed under neither `+`, the caps, nor `max`, the cost.)
- **(B2) The fold.** If `Step` is `DownClosed` and `ClosedUnder op`, op ∈ {min, max, +}, and `s` is a course with `s (T+p) = s T`, p ≥ 1, then `x := op_{T ≤ t < T+p} s t` has `Step x x`. For `+` it is enough that `s T ≤ s (T+p)`.
- **(B3) Holding.** The following are equivalent: (1) `∃ x, Standing (Move W) D x`; (2) some course of `Move W` has a kind `k` with `D k` present at every step from some step on; (3) some `ClosingCourse W s` has `Live D (s t)` for all t.
- **(B4) The configuration grain, exactly.** For every n: some closing course from n keeps D for ever ⇔ some closing course from n reaches a configuration n' with n' ≥ x for some standing x. V_D and the set of starts of a keeping closing course are both up-sets (the program checked the first only).
- **(B5) Changing.** In case (iii): (a) in every course that keeps D, every kind of D is absent at infinitely many steps; (b) every closing course, from every start, has a first step t with `¬ Keeps (Move W) D (s t)`, and from there every course of every selection ends D; (c) every course that keeps D forms, at infinitely many steps, a kind absent at that step; (d) the sum of any cycle of V_D is a standing population of the same recipes and capacities with caps p · C.
- **(B6) Where (iii) can be.** If some course keeps D under `MoveUncapped W`, then `∃ x, Standing (MoveUncapped W) D x`. If some course keeps D under `MoveFree W`, then `∃ x, Standing (MoveFree W) D x` (within C). So case (iii) needs both the caps and the cost.

Read as the statement the brief aims at: from a configuration, under a closing way of selecting, the course either goes on (holding a form: it reaches a configuration at or above a standing population) or passes a step from which no course keeps the formation; which of the two is exact by (B4); and at the grain of the law, where the formation can be kept only with its forms changing, no closing selection keeps it from anywhere, and that can happen only where the source is finite and keeping costs (B5, B6). By the way of selecting: closing or not. By what keeping costs: free support excludes (iii). Not by what is registered.

**Proof sketch.**

- B1. min: Σ_k min(b_k, b'_k)·R_kj ≤ min(Σ_k b_k R_kj, Σ_k b'_k R_kj) ≤ min(c_j n_j, c_j n'_j) = c_j·min(n_j, n'_j), and min(b, b') ≤ C. +: the sums add; b + b' can pass C, so + needs no caps. max, support free: if max(b, b')_k > 0 then b_k > 0 or b'_k > 0, so R_kj ≤ c_j n_j or ≤ c_j n'_j, each ≤ c_j max(n, n')_j; max(b, b') ≤ C. With cost, max fails: n with one act, b = (1,0), b' = (0,1), max needs two. DownClosed: fewer births need fewer acts.
- B2. Fold the p steps `s t → s (t+1)` by `op` (B1 applied p − 1 times): `op_t s t → op_t s (t+1)`; on a cycle both sides are x. For +: x → x − s T + s (T+p) ≥ x, and DownClosed gives x → x.
- B3. (1⇒3): x, x, x, … is closing. (3⇒2): along a closing course the set of kinds present never grows, so it is constant from some T; `Live` gives a kind of D in it, present at every t ≥ T. (2⇒1): put m j := min_{t ≥ T} s t j (exists in ℕ). For each j take t ≥ T with s t j = m j: Σ_k m_k R_kj ≤ Σ_k s(t+1)_k R_kj ≤ c_j·s(t)_j = c_j m_j; m ≤ C; m_k ≥ 1. No periodicity is used, so this holds with caps or without.
- B4. ⇐: if n' ≥ x, then x R ≤ c∘x ≤ c∘n' and the kinds of x are among those of n', so n' → x is a closing move; then x, x, …. ⇒: on a keeping closing course, the m of B3 over its tail is standing and the tail's first configuration is ≥ m. Up-sets: from n' ≥ n every move from n is a move (more acts), and every closing move from n is closing from n'.
- B5. (a) a kind of D present from some step on gives a standing x by B3 (2⇒1). (b) a closing course that kept D for ever gives one by B3 (3⇒1); so it ends; a configuration that is not `Live` is not in V_D; the first t outside V_D is the step; the complement of V_D is closed under moves (a live configuration with a successor in V_D is in V_D). (c) if from some step on no absent kind is formed, the course is closing from there; B3. (d) B2 with + under `MoveUncapped`, and the sum is at most p · C.
- B6. Uncapped: Dickson's lemma (ℕ^K is well-quasi-ordered) gives T < T' with s T ≤ s T' on the keeping course; B2 with +; the sum is `Live` since s T is. Free: with caps the course is in a finite box, so it is eventually periodic; B2 with max; the max is ≤ C and dominates a live configuration.

## 4. Which of R1 to R7

- **R1, had.** Tokens of a kind exist only as other tokens' acts formed them (recipes); the formation's kinds can rest on each other (in L* below each partner is formed from the other).
- **R2, had, in the better form.** The ground is itself a kind, re-formed from its own acts; its cap is the finite source; what comes back is c · (what is left); it runs out when its acts are given to others, and a ground with no token gives nothing for ever. What is not had: a level that falls over many steps; in the built cases it is lost in one step.
- **R3, had.** An act serves one forming (`Move`); taking it out is `MoveFree`, and B6 shows it does work.
- **R4, partly.** The selecting of which kinds are formed is set again from what it formed last (closing). The "lock" that comes about is only that the kinds present never come back once gone, and it follows in one line from the class; what is concluded is that in case (iii) every such selection ends. The share as a ranking is idle in Theorem B.
- **R5, had.** V_D is a kernel of choice among moves; B5(b) gives the first step after which no course keeps.
- **R6, left out.** Nothing is read; there is no revision.
- **R7, partly.** In case (iii) the formation goes on only with its forms coming and going (B5a), and no selection that only re-forms what is there can do it (B5b); the cycle is a population the source cannot carry at once, spread over time (B5d). "More and more future" is not had: no new kinds arise.

Why this cut first: the angle's question was what a finite source and a cost do to October's renewal closure, and that has an exact answer at the grain of the law (B6: only in the corner where the moves are closed under min alone can going on need change). Adding a reading or a ranking before that is settled would make the statement hang on a rule chosen by hand, as the toys of 20 and 21 November did.

## 7. Where it is weakest

1. **T5 fails.** No old law comes out with its statement unchanged; on the lock side nothing even has the right parts.
2. **Generational tokens.** "Holding" here means re-forming the same kinds every step. With tokens that persist (October's spans) holding may need no re-forming, and whether B3's min argument and case (iii) survive is not checked. Part of the change found at the configuration grain is forced by the generational step itself.
3. **Case (iii) is one mechanism**, rare in what was searched (52 of 81,536 laws on three kinds, none of 6,000 on four). That it needs a finite source and a cost is proved; that it is common, or that it is the second way Ren points at, is not.
4. **The lock is near handed in.** Closing is a premise on the class, and the face lemma is one line. What is concluded is only that in case (iii) every closing selection ends.
5. **The share as a ranking is idle** in Theorem B; it works only in built cases of one rule.
6. **"Uses up what it rests on" is shown in instances, not stated**: B5(b) says the closing course ends, not that the ground goes first. In L* one ending is the ground's renewing act given away, the others a partner lost.
7. **Nothing runs down over many steps, nothing is read** (R6), and no new kinds arise, so "more and more future" is not touched.
8. **The mathematics may be known.** B6's uncapped half is the self-covering argument of vector addition systems (Rackoff) made into one step by additivity; min-closure of downward-closed linear constraints is standard. A reader may find B6 stated in Petri-net terms.

What would refute it: a law in case (iii) with no caps or with free support (against B6); a closing course keeping D in a law with no standing population (against B3); in case (iii), a keeping course with one kind of D present from some step on (against B5a); C1 failing in a larger family; or a reader showing that "closing" is the package's lock and B5(b) older laws in a row.
