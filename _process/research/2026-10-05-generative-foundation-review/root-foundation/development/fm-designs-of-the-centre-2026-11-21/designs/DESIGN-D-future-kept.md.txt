## 1. The design in ten lines

1. Configurations and steps are those of any `Process S A`; a course is a `Run P`. For instances there is one small model, RS: a level `L ≤ C` and, for each class, the life left to its unit; a move is a set of classes to form; a formed unit takes its forming cost from the level, a present unit adds or draws its amount, a unit whose need the level does not meet is lost, and a unit not formed again lapses.
2. A family of guards `G : X → S → Prop` is the reading in which the future is told (in RS: "a unit of class x is present").
3. The future at a configuration is what can still be kept from it: `Kept s x := Keepable P (G x) s` (`JointKeeping.Keepable`: some run from `s` stays within the guard). That is the Lean's `adm` of `Reaching` set to keepability.
4. Along a course it lies between two chains the Lean already has laws for: `Held n` (what the course itself holds from step `n` on), which never loses, and `Possible n` (`Reaching.Possible` at that `adm`), which never gains. `Held ⊆ Kept ⊆ Holds`, `Kept ⊆ Possible`.
5. A way of selecting is what picks the move: a rule from what it registers (nothing; which guards hold; the configuration). Its course is one run.
6. **Main statement, part 2.** A course loses nothing of the kept future from step `N` on exactly where, from `N` on, the kept future is what the course itself holds for good. So the Lean's keeping widening, said of the kept future, holds exactly of a course that forgoes nothing and goes on beginning to hold.
7. **Part 3.** The guards that stay kept along a course are kept together at its start. So from a configuration whose kept guards are not kept together, every course loses one; and where they are, some course loses none.
8. **Part 4.** Where one move is at least as good as any other from any configuration below (in RS: no class draws and forming is free), the kept guards are always kept together and the way that registers nothing and always takes that move forgoes nothing and takes all that is possible. Forced loss needs keeping to cost.
9. Both ends from one start of one RS instance: a way that registers nothing closes everything in six steps; a way that registers what holds takes all three classes with nothing lost. The two courses share their first three configurations.
10. What it does not give: which way closes and which takes, short of running the course; a lock; a share. And part 2 reads as a negative for the direction: a way of selecting that forgoes anything does not keep widening in the Lean's sense.

## 2. Definitions

Existing, used as they stand: `Process`, `Run`, `Run.onward`, `Reach`, `JointKeeping.Keepable P g s := ∃ r : Run P, r.state 0 = s ∧ ∀ n, g (r.state n)`, `Keepable.start`, `Keepable.mono`, `KeepableStep.keepable_step_iff`, `Reaching.Possible P adm s x := ∃ t, Reach P s t ∧ adm t x`, `Run.possible_of_next`, `Run.not_possible_returns`, `WideningOnTheMap.includes`, `KeepsWideningFrom`.

New (for `P : Process S A`, `G : X → S → Prop`, `r : Run P`):

```
def Holds  (r) (n : Nat) (x : X) : Prop := G x (r.state n)
def Kept   (r) (n : Nat) (x : X) : Prop := Keepable P (G x) (r.state n)
def Held   (r) (n : Nat) (x : X) : Prop := ∀ k, G x (r.state (n + k))
def Poss   (r) (n : Nat) (x : X) : Prop :=
  Reaching.Possible P (fun t y => Keepable P (G y) t) (r.state n) x      -- no new notion
def Together (s : S) (R : X → Prop) : Prop :=
  Keepable P (fun t => ∀ x, R x → G x t) s                               -- no new notion
structure Dominates (le : S → S → Prop) (top : A) (nextTop : S → S) : Prop where
  refl : ∀ s, le s s
  step : ∀ s, P.step s top (nextTop s)
  only : ∀ s t, P.step s top t → t = nextTop s
  dom  : ∀ s ŝ a t, le s ŝ → P.step s a t → le t (nextTop ŝ)
  up   : ∀ x s ŝ, le s ŝ → G x s → G x ŝ
```

The model RS (an instance): `m` classes, life `ℓ ≥ 1`, cap `C`; for each class `x`: `w x : Int` (what a present unit adds to the level each step; negative: draws), `c x : Nat` (forming cost), `n x : Nat` (need), `base x : Bool` (formable from nothing), `sup x` (classes whose presence lets `x` be formed). Configuration `(L, a)`, `0 ≤ L ≤ C`, `a x ∈ {0..ℓ}` the life left (0: absent). Move: `F ⊆ classes`. `next (L, a) F`: going through the classes in order, `x ∈ F` is formed if `a x > 0 ∨ base x ∨ ∃ y ∈ sup x, a y > 0` (read at the configuration the step starts from) and `c x ≤` what is left of `L`, which it then lowers; `a¹ x = ℓ` if formed, else `a x − 1` (not below 0); `L¹ = clamp(L − costs + Σ_{a¹ x > 0} w x, 0, C)`; `a' x = a¹ x` if `n x ≤ L¹`, else 0; `L' = L¹`. `P.step s F t := t = next s F`. Guards `G x (L, a) := a x > 0`. A way of selecting is `rule : O → Move` with `obs : S → O`; its course is the run of `s ↦ next s (rule (obs s))`. Three readings were run: `O = Unit` (registers nothing), `obs = ` which guards hold, `obs = id`.

## 3. The main statement

**Theorem (the kept future along a course).** For every process `P`, family `G`, run `r`, with no premise in parts 1 to 3:

1. *Order.* `Held n ⊆ Kept n ⊆ Holds n`, `Kept n ⊆ Poss n`, `Held n ⊆ Held (n+1)`, `Poss (n+1) ⊆ Poss n`. A guard not kept at `n` and kept at `n+1` does not hold at `n`.
2. *Losing nothing is forgoing nothing.* For every `N`:
   `(∀ n, N ≤ n → ∀ x, Kept n x → Kept (n+1) x) ↔ (∀ n, N ≤ n → ∀ x, Kept n x ↔ Held n x)`.
   Hence `KeepsWideningFrom (Kept r) N ↔ (∀ n ≥ N, ∀ x, Kept n x ↔ Held n x) ∧ ∀ n ≥ N, ∃ k x, Held (n+k) x ∧ ¬ Held n x`.
3. *What stays kept is kept together.* For every `N`: `Together (r.state N) (fun x => ∀ n, N ≤ n → Kept n x)`. Equivalently, for every `s` and `R`: `Keepable P (fun t => ∀ x, R x → Keepable P (G x) t) s ↔ Together s R` (keeping what is each keepable is keeping all; with one guard, `Keepable` is idempotent). Hence: some run from `s` never loses a guard kept at `s` ↔ `Together s (Kept at s)`; and if not, for every run from `s`, not all guards kept at `s` are kept at every step.
4. *Where one move forgoes nothing.* If `Dominates le top nextTop`, then for the run `r̂` from `s` that takes `top` at every step: `Kept n x ↔ Held n x` for every `n`, `Together s (Kept at s)`, and `Poss 0 x → ∃ n, Held n x`. In RS, `top` = "form every class" with `(L, a) ≤ (L̂, â)` pointwise dominates when `w x ≥ 0` and `c x = 0` for every `x`.

**Proof sketch.**
1. `Held ⊆ Kept`: `r.onward n` starts at `r.state n` and stays in `G x`. `Kept ⊆ Holds`: `Keepable.start`. `Kept ⊆ Poss`: `Reach` is reflexive. `Held` up: shift `k`. `Poss` down: `Run.possible_of_next`. Last sentence: `keepable_step_iff`, right to left.
2. Right to left: `Kept n = Held n ⊆ Held (n+1) = Kept (n+1)`. Left to right: fix `n ≥ N` and `x` with `Kept n x`; by induction on `k`, `Kept (n+k) x`; by `Keepable.start`, `G x (r.state (n+k))`; so `Held n x`. The other inclusion is part 1. The corollary: the first half of `KeepsWideningFrom` is the left side (induction on the stretch); in the second half replace `Kept` by `Held`.
3. Put `R x := ∀ n ≥ N, Kept n x`. On `r.onward N`, at each step `k` and each `x` with `R x`, `Kept (N+k) x`, so `G x` holds there (`Keepable.start`). The equivalent form: left to right by `Keepable.mono` with `Keepable.start`; right to left, each state of the keeping run is the start of its own tail.
4. By induction `le (r.state n) (r̂.state n)` for every run `r` from `s` (`dom`). If `r` keeps `G x`, `up` gives `G x (r̂.state n)` for all `n`. The tail of `r̂` is the `top`-run from where it stands (`only`), so the same holds at every step. For the last clause, a configuration where `x` is keepable is reached at some step `k` of a run that then keeps it; `r̂` dominates that run. RS: with no draws and no costs, a larger configuration forms at least the same classes under a larger set, so lives, level and survivors are at least as large.

**Premises, marked.** Parts 1 to 3: none. Part 4: `Dominates`, *structural* (it says the process has an order and a greatest move; it is checked from RS's numbers). In RS, handed in: `w`, `c`, `n`, `base`, `sup`, `ℓ`, `C`. The level's fall comes about from draws and costs. The giving is by units that must themselves be kept, but the amount `w` is handed in and comes from across the boundary. The lock, the share and the reading's revision are absent. The turn is a move chosen, not derived.

**What part 2 says of the direction.** "Nothing held is lost" is the first half of the Lean's keeping widening. Said of what can still be kept, it holds exactly where the course has no kept future but its own. A way of selecting that passes over something it could have kept loses it, by definition of the chain. So the second way cannot be both a selecting among futures and a keeping widening of the kept future. In instance I3 below a course ends holding everything possible only by first losing a guard it kept.

## 4. R1 to R7

- **R1, partly.** A unit of a class is there only if formed from a unit of its class or of a supporting class. Support is asked for forming only.
- **R2, half.** The level is finite and runs down by draws and costs. What adds to it is units in the model that lapse unless kept. The amount added is not taken from anything in the model.
- **R3, partly.** Keeping a class costs the level (forming cost every `ℓ` steps at least). It is not a cost to the keeper's own standing.
- **R4, left out.** No share, no rule set again from what it favours. Parts 1 to 3 hold of every course, locked or not, so the cut is before the lock, not instead of it.
- **R5, yes.** `Keepable`, and the step of no return as the step at which a guard leaves `Poss`.
- **R6, the first half.** A reading enters twice: the guard family, and what the rule registers. No revision.
- **R7, yes, with a negative.** Part 2 relates a course, and so a way of selecting, to widening of what can be kept after it.

This cut first because the angle's question is prior to the lock: what any way of selecting does to what can be kept.

## 7. Where it is weakest

1. Parts 1 to 3 are a few lines each, and part 2 is true of any chain between what is held for good and what holds. Keepability earns its place only in part 3 and in the gap between holding and kept.
2. It does not state the centre. It has both ends on one course and an exact law of one of them, but which way closes and which takes is found only by running; part 4 is sufficient, not exact.
3. No lock and no share, and no old law of the lock's side as a case.
4. RS adds to the level from nowhere in the model. The adding unit must be kept at a cost, which is less than 17 November's failure and the same kind.
5. `Keepable` asks for some run. With moves of several outcomes and keeping against all of them, `Held ⊆ Kept` fails and part 2 would need each move to have one outcome.
6. Keeping widening for ever was not run. On paper: with a finite cap, the classes with a positive forming cost held at once are at most `ℓ·C`.

It is refuted as a contribution by a statement of part 2 or 3 already in the Lean, or by a reader showing that part 3 is `Keepable.each` with a definition unfolded. Part 2's reading is refuted if "more and more future" can be given an order under which a course that forgoes something still widens and the Lean's law applies to it unchanged; the candidate here (`Held` grows, `Poss` not narrowed, `Kept` free to lose, as in I3) has no law.
