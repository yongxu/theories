## The two facts everything below turns on

1. **The file's step, as it stands (PC ll. 33–44):**
```lean
def allocated (N k : Nat) (active : Bool) (r : Nat) : Nat :=
  if active then min N (r + k) else r - k
def inflow (N : Nat) (active : Bool) (r : Nat) : Nat :=
  r + if active then 3 * (N - r) else 0
def next (N fee cap k : Nat) (s : State) : State :=
  let active := funded fee s
  { renewing := allocated N k active s.renewing
    reserve := min fee (s.reserve - (if active then fee else 0) + inflow N active s.renewing)
    capacity := min cap (s.capacity + s.renewing - (N - s.renewing)) }
```
2. **The boundary's proof (PC ll. 504–514)** is `funding_iff_ledger` (l. 496, itself a case split on `actual_or_unfunded_ledger`, l. 464, a 33-line induction), then `contributions_bounded` (l. 456) and the witness `s.renewing`. All of the boundary's content is in l. 464 and in `contributions_stop`/`off_count_bound` (ll. 407, 446). Any package law that "has" the boundary must either do the work of l. 464 or take it as a premise.

**A finding none of the readers made (by program, not Lean).** The boundary's premises `hr : s.renewing ≤ N` and `hf : fee ≤ N` are not needed for its statement. Over 200,000 random cases (N to 6, fee to 12, renewing to 10, reserve to 15, quotas 1 to 4), `(∃ t, fee ≤ reserve_t) ↔ fee ≤ B + available k r r` held with no failures, including where `r > N` and `fee > N`. The bounded form `(∃ j ≤ n, fee ≤ reserve_j) ↔ fee ≤ B + available k r n` also held with no failures, with quotas from 0, so it does not need `hk` either. The file needs `hr` and `hf` only because l. 464's funded branch uses `funded_step`. This matters for Lasting below.

### 1.1 `RegimeMargin.Coupled.Indexed.ends_iff_below_within` (l. 2984): who is right

Claimed by: level-and-rule (Fable), Q4 ("N2 holds, in shape … its premise `KeepsBelow` is false of the file's `next` as written (it fails where `renewing > N`)"); Astra, Q9 ("a restricted **paper case** … clipping inputs to `N,fee`").

OPENED. The premise:
```lean
-- RegimeMargin l. 2818
def KeepsBelow (f : (ι → Nat) → (ι → Nat)) : Prop :=
  ∀ x y, Below Drawn.whole x y → Below Drawn.whole (f x) (f y)
-- l. 2117: def Below (x y : ι → V) : Prop := ∀ i, D.le (x i) (y i)
```
and the conclusion `EndsUnder f i (setAt y i a) ↔ a < thresholdWithin f cs B hi y i`, where `EndsUnder f c s := ∃ N, ∀ k, (Law.run f s).state (N + k) c = 0` (l. 2814) and `thresholdWithin` is `leading` of a finite check run for `(B + 1) ^ cs.length` steps (ll. 2953–2960).

**Both are right, about different statements.**
- **Fable is right of `next` as written.** `KeepsBelow` quantifies over every state. Take `x = ⟨N+5, fee−1, c⟩` and `y = ⟨N+5, fee, c⟩` with `k = 1`, so `x ≤ y` coordinatewise. `x` is unfunded, and `allocated` gives `N+5−1 = N+4` (l. 34). `y` is funded, and gives `min N (N+6) = N`. Then `N+4 > N`, so the order fails. Generally the count coordinate fails exactly where `r − k > N`. A second failure the reader did not name: the reserve coordinate fails where `fee > N`. At `r = 0`, `x = ⟨0, fee−1, c⟩` goes to reserve `fee − 1`, and `y = ⟨0, fee, c⟩` goes to `min fee (0 + 3N)`, which is below `fee − 1` once `3N < fee − 1`. So the premise needs `fee ≤ N` as well as `r ≤ N`.
- **Astra is right of a projected, clipped step.** Fix one constant quota `c ≥ 1`, with `1 ≤ N` and `fee ≤ N`. Take `ι` with two conditions (count, reserve), drop capacity (nothing reads it, ll. 39–44), and define
  `f x := let r := min N (x count); b := min fee (x reserve); (allocated N c (decide (fee ≤ b)) r, min fee (b + r))`.
  - **Order.** `min` is monotone. In the count coordinate, the unfunded branch `r − c` is below the funded branch `min N (r' + c)` whenever `r ≤ r' ≤ N`. The reserve coordinate is a clipped sum. So `f` keeps the order at every state, and `KeepsBelow f` holds.
  - **Agreement with the file.** On the box `r ≤ N`, `b ≤ fee`, `f` agrees with the file's step projected. This is `unfunded_step` (l. 50) below the fee. At `b = fee`, it is `funded_step` (l. 57) with `hr` and `hf`: the funded reserve is `fee`, and `min fee (fee + r) = fee`. The box is kept (`count_bound` l. 68, `post_step_bounds` l. 570).
  - **The other premises.** `StaysWithin f B (setAt y count N)` holds with `B := N` (because `fee ≤ N`). `covers` holds for a two-element list.

**The restricted statement that is true.** Fix `1 ≤ c`, `1 ≤ N`, `fee ≤ N`, `b ≤ fee` and `a ≤ N`, and let `f` be the clipped two-coordinate step at constant quota `c`. Then:
`EndsUnder f count (setAt y count a) ↔ a < thresholdWithin f [count, reserve] N N y count`, where `y reserve = b`.
- PC l. 524 (shortfall) and l. 553 (enough, with `1 ≤ N`, so the count is `N ≠ 0` from some step on) give `EndsUnder … ↔ b + available (fun _ => c) a a < fee`.
- So `thresholdWithin` is the least `a` with `fee ≤ b + available (fun _ => c) a a`. That least `a` exists and is at most `N`, because `available` at `a = N` is at least `N`, which is at least `fee`.

**Class (b).** What the restriction leaves out:
- a constant schedule only, where the file has every `k : Nat → Nat`;
- clipped inputs, or a domain cut to the box;
- capacity projected away;
- the third conjunct of either regime;
- the threshold as an amount.

The package's statement says that an exact threshold in the initial count exists for an order-keeping, bounded step. It does no work toward the file's amount. The file's ll. 464, 524 and 553 compute the package's `thresholdWithin`, not the reverse. No line of the file's proof is replaced; the instance would add the clipping and the agreement on the box.

### 1.2 `Lasting.reaches_iff_of_exact` (l. 625) with `Funnel` and `Basin` (ll. 568–578)

Claimed by: Astra, Q7 ("A paper case of bounded reaching"); also Q4 for `orbit_reaches_iff_variant` ("This is a case for bounded reaching").

OPENED:
```lean
structure Funnel … where
  base : ∀ x, F 0 x → target x
  descends : ∀ k x, F (k + 1) x → target x ∨ ∀ a, adm a → F k (f x a)
structure Basin … where
  holds : ∀ k x, target x → L k x
  gathers : ∀ k x, (∀ a, adm a → L k (f x a)) → L (k + 1) x
theorem reaches_iff_of_exact {C} (funnel : Funnel f adm target C)
    (basin : Basin f adm target C) (n : Nat) (s : S) : Reaches f adm target n s ↔ C n s
```

**What `C` must be.** The state is `(j, s)` with a clock `j` (the quota varies), `adm := fun _ => True`, `f (j, s) () := (j+1, next N fee cap (k j) s)` and `target (j, s) := fee ≤ s.reserve`. Then
`C n (j, s) := fee ≤ s.reserve + available (fun i => k (j + i)) s.renewing n`, which is Astra's `C`, checked.

**What discharging it is.**
- `base`: `available … 0 = 0`, so `C 0` is the target. One line.
- `holds`: if `fee ≤ B` then `fee ≤ B + anything`. One line.
- `descends` and `gathers` both need the first-term identity `available k' r (n+1) = r + available (fun i => k' (i+1)) (r − k' 0) n`.
  - The file has no such lemma. PC l. 387 adds the last term (`available k r (t+1) = available k r t + offCount k r t`), so this is a new induction that shifts `offCount` with the schedule.
  - Then, on an unfunded state, `unfunded_step` (l. 50) together with clipping at the fee.

That is the induction of `actual_or_unfunded_ledger` (l. 464) done again, in the other order of summation. The instance, read through `reaches_iff_orbit` (l. 739), states `(∃ j ≤ n, fee ≤ reserve_j) ↔ fee ≤ B + available k r n`.

**Class (a) for that bounded statement. A re-telling by the addendum's point 3.** Each of the package law's four fields is discharged by the file's own arithmetic, re-derived, and the package law does no further work: its proof is two applications of the field structures. It is not the file's boundary: the boundary still needs `contributions_bounded` (l. 456) at `n = r` to go from `∃ j ≤ n` to `∃ t`. No older proof gets shorter. Astra says the same ("None identified"), and that holds.

One thing the instance would say that the file does not state: the bounded reach-iff with no `hr`, `hf` or `hk`. `descends` and `gathers` use only `unfunded_step`, which has the premise `B < fee` alone. By program (above) that statement is true. It follows equally from a premise-free variant of l. 464 inside the file, so it is no join.

`orbit_reaches_iff_variant` (l. 831, OPENED: `(∃ k, k ≤ n ∧ target (Law.orbit next s k)) ↔ ∃ V : S → Nat, V s ≤ n ∧ ∀ x, V x ≤ n → target x ∨ V (next x) < V x`) holds of every determined law with a decided target. **A candidate nobody tried, found by search.**
- **The law.** `Countdown.completes_iff` (OPENED, l. 164): `(∃ t, ticks tick (work s + 1) s = some t ∧ done t) ↔ work s + 1 ≤ fuel s` under `CountedWork`. That structure asks, while busy, that one tick does one unit of work for one unit of fuel, with `finish` and `stall` (ll. 101–105).
- **The map.** Ticks are single units of contribution, not the file's steps; `work + 1 := fee − B`; `fuel :=` what the ledger can still pay. The right side then reads `fee − B ≤ available k r r`, which is the boundary for `B < fee`.
- **Why it fails.**
  - (1) A file step pays `r_t` units at once, so `advance` (`work t + 1 = work s ∧ fuel t + 1 = fuel s`) holds only of a unit-tick refinement. Mapping unit ticks back to steps is l. 464 again.
