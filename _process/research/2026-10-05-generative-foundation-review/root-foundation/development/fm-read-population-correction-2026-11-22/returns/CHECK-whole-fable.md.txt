## 3. The claims that carry the conclusion, opened word for word

**(i)** OPENED l. 576–579: `(hN : 1 ≤ N) (hr : s.renewing ≤ N) (hf : fee ≤ N) (hk : ∀ t, 1 ≤ k t) (enough : fee ≤ s.reserve+available k s.renewing s.renewing) : ∃ t, ∀ u, history N fee cap k s (t+u) = ⟨N,fee,cap⟩`. Literally one state at every step from some step on.

**(ii)** OPENED l. 594–595: `(hb : B < fee) : next N fee cap k ⟨0,B,0⟩ = ⟨0,B,0⟩`, one step, every `N`, `cap`, `k`. OPENED l. 516–519: `(∃ t, fee ≤ (history N fee cap k (topup fee extra s) t).reserve) ↔ fee-(s.reserve+available k s.renewing s.renewing) ≤ extra`. At `s = ⟨0,B,0⟩`, `available k 0 0 = 0` by l. 386, so funded at some step exactly where `fee − B ≤ extra`. Then `topup` gives `⟨0, fee, 0⟩` and l. 576 applies with `enough` as `fee ≤ fee + 0`. The composition ("mine" in the ways return; the same in file and lock) is sound, under `1 ≤ N`, `fee ≤ N`, `∀ t, 1 ≤ k t`; it needs only the definition of `topup` and l. 576. By arithmetic for N ≤ 6: a top-up of `fee − B` or more comes to `⟨N,fee,cap⟩`, a smaller one never funds. So the region is left by a transfer of at most the fee, at any step, and capacity returns to its cap. No theorem of the file states the composition.

**(iii)** Confirmed. Ll. 524 and 553/576 share `hN hr hf hk`, split on `<` and `≤` of one expression, and each is one-way. Read whole: no theorem conjoins them, excludes one by the other, or gives an iff for either.

**(iv)** Sound, by hand; not a theorem of the file. For `1 ≤ k t`, `r ≤ available k r r ≤ triangle r` (ll. 398, 427, 432). So every such schedule funds where `fee ≤ B + r`, none where `B + triangle r < fee`, and between them the schedule decides. By arithmetic on N ≤ 5: of 355 starts 11 are in the band, each with both outcomes, none outside it. The file's start `⟨3,0,12⟩` at `N = fee = 6` is in the band (3 < 6 ≤ 6). Its own pair for the outcomes is l. 367 (`speed_one_eventually_constructive`) with l. 353 (`growth_eventually_destructive`, which concludes `renewing = 0` and `capacity = 0` and does not state the reserve); ll. 348 and 350 show the funding and the closing.

**(v)** Said too widely. OPENED l. 496: `funding_iff_ledger` has no premise on `k`. Without `1 ≤ k t` the cutoff at step `s.renewing` (l. 504) and the closure of `Doomed` (l. 132) fail; "funded at some step exactly where the ledger covers the fee at some step" stays. By arithmetic with `k = 0`: `N = fee = 5`, start `⟨1,0,_⟩` funds at step 5 while `fee ≤ 0 + available k 1 1` is false; a start with none renewing below the fee never funds.

**(vi)** OPENED `ResponseCapacity` l. 318–320: `(∀ t, 0 < (run demand (fun _ _ => 0) s t).support) ↔ 0 < s.support ∧ demand ≤ s.response`, no premise. L. 407–410: `(hopt : LocallyOptimal demand policy s) (t : Nat) (hv : 0 < (run demand policy s t).support) : run demand policy s t = run demand (fun _ _ => 0) s t`. The composition is sound on paper: for a locally optimal policy, alive at every step gives the zero course alive (l. 407), hence the right side (l. 318); the other way by induction with `LocallyOptimal`'s second conjunct at `i = 0`. The file states only the halting half for such policies (l. 438). Its lasting side, l. 249–251: `run … = ⟨s.response,s.support+demand*t⟩`. One number rises by `demand` a step without bound while the other stands; with `demand = 0` nothing moves.

(c) That "can no longer be turned" means by no schedule: true (ll. 594, 132); by a transfer of at most the fee it is turned (§3(ii)).
