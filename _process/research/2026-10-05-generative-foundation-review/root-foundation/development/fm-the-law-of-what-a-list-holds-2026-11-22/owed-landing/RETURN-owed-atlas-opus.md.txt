**2(b) What a mapping row is**
- Fields: `{family, source: "lister", binders: [{position, name, type, premises:[ids]}], takes_unbound: {id: kind}}`.
- `position` is the 1-based index over every binder of the compiled constant's type. Implicit and type binders are counted too, but only binders whose type is a proposition get a row. lister.py `aaRow`:
  - `forallTelescope ci.type fun xs _ => do … for x in xs do i := i + 1; let t ← inferType x; if ← isProp t then … "position": toString i`
- The signature is therefore the elaborated one, with the section variables Lean included. It is not the source text's explicit binders. It is not the core run's printed statement either: the receipt holds `{'kind','name'}` only, which I checked on its Becoming.Junctures entry.
- Evidence that the current row follows this rule: the 22 Oct signature log (`becoming-checks/20261022T064310.304329Z/BecomingJuncturesSignatures.log` l.114-119) prints `∀ {S} {A} {P} {s} {all} {edge}, (every) → (decides) → Returns P s → ∀ {y}, Reach P y s → …`. That makes every=7, decides=8, returns=9, y=10 (not a proposition, so no row), reach=11, which matches the row.
- Lean 4.29.1 includes a section variable only where the header mentions it. The same log shows `any_congr : ∀ {S} {p q}` and `leads_bound : ∀ {S} {s} {all} {edge}` (no A or P).
- So the new header `(every : ∀ x, x ∈ all) {y : S} (reach : Reach P y s) : ∃ as, as.length ≤ all.length ∧ Trace P y as s` elaborates to `{S}1 {A}2 {P}3 {s}4 {all}5 every6 {y}7 reach8`. `edge` drops out because nothing in the header names it.
