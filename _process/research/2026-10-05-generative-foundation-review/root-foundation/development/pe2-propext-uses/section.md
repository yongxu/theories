- **How it was read.** `restore.py` takes a periphery receipt's compile order and, for every module, the bytes whose sha256 the receipt records (from the commit of main it names, else from its run folder's copy), computes the checkers' step keys and restores each `.olean` from the shared cache: all 24 closures were restored without compiling. `Uses.lean` then reads each audited declaration's kernel term. It computes the axiom dependency as Lean's `CollectAxioms` does, which agrees with every recorded report. A proof (a declaration whose type is a proposition) is classed by what in its term is on `propext`. A definition's term is walked in data position. Every proof argument on `propext` is placed by where it goes: carried (a constructor's field, a quotient primitive, `decidable_of_iff` and the like) or taken apart (the major premise of a cast or of a recursor of an inductive proposition, well-founded recursion, a proof given to a local function). A proof given to another definition is followed into that definition's body. A proof that is on `propext` only because it mentions a value on `propext` (in an implicit argument) counts as a use of that value.
- **The proofs (444 in the periphery).** 35 apply `propext` in their own term: the identification `simp` or `rw` makes when it rewrites along an iff. 364 get it through theorems they use. In 58 of them every such theorem is from Init or Mathlib, mostly `simp`'s identifications of propositions (`eq_self : (a = a) = True`, `eq_false`, `ite_cond_eq_true`), in 219 every such theorem is from the repository, and 87 use both. 45 use no theorem on `propext` at all: their report has it only because they mention a definition that has it. In every case `propext` stands where an identification of interderivable propositions is made inside a proof, and by definitional proof irrelevance no value depends on which proof it is.
- **The definitions (44 `def` and one `abbrev`).** 24 only carry a proof on `propext`: decidability built from an iff (`List.instDecidableMemOfLawfulBEq` given `Nat.instLawfulBEq`), constructor fields, quotient lifts. 14 (`MachineInstances.revises`, `adoptsRule`, `sceneStep`, `enact`, `heard`, `heardAlong`, `learningRecord`, `Groups`; `ProtocolInstances`' four; `VersionedTaskInstances.reviews`, `clears`) reach `propext` only through `Nat.land`. That route belongs to Lean's own compilation, not to the periphery. A match with a wildcard over an inductive's constructors compiles to `_sparseCasesOn`, whose `else` branch receives a proof of `Nat.hasNotBit m t.ctorIdx`. That statement names `Nat.land`, whose definition (well-founded `Nat.bitwise`) has a termination proof on `propext`. The branch ignores the proof, and the kernel computes `Nat.land` on literals itself without unfolding it. `reduction/machine-instances.lean` checks `revises .revise = true` and `revises .retry = false` by `decide` and by `rfl`.
- **The seven the analysis left open.** All are library internals. (i) `IdealsCorrespondence.ofList` and `listIdeal`: a bound proof given to `getElem`, carried into the list's index; `ofList [5, 6, 7]` computes its letters by `decide` and `rfl`. (ii) `LearningCorrespondence.updating` and `TransmissionCorrespondence.historyOut` and `process`: `Matrix.vecCons` reaches `Fin.induction.go`, whose base case is a cast (`Eq.mpr`) along `Fin.mk_zero`. `Eq` is K-like, so the kernel reduces the cast whenever its ends are definitionally equal, as they are at a closed index. `![1, 2, 3] 0 = 1` and `DevelopmentalMemory.first 0 = 1` hold by `rfl`. (iii) `EntropyProduction.ExpectedDissipatesOn` and `Fluctuation.coin`: Mathlib's integral and Dirac measure. Read at the pinned revision, the proofs go into proof fields (`TopologicalSpace.mkOfClosure`, `MeasurableSpace.copy` through `mkOfClosure`), and `OuterMeasure.toMeasure` hands `Measure.ofMeasurable` a set function that ignores its measurability proof. These are classical values, which reduction does not compute in any case. The same check covers the library values that 49 proofs only mention: besides these seven, `JointContinuation.zipPlan` and `compatible`, whose matches on `n + 1` go through `Nat.elimOffset`, compute on closed plans by `rfl` (`reduction/continuation-correspondence.lean`).
- **The core's generated lemmas.** Each of the 196 `injEq` lemmas is `Eq.propIntro inj (injEq_helper …)`, and `Eq.propIntro h₁ h₂` is `propext ⟨h₁, h₂⟩`: it identifies `(mk a = mk b)` with `(a = b)` for interderivable propositions, exactly the lumping. None mentions a value on `propext`, and no core source declaration uses one, since every core source declaration's report is empty.
- **The second kind: none, and what avoiding it would cost.** No periphery definition computes a value through an identification of propositions, so nothing needs restating with `↔`. What remains is the encoding. `reduction/sparse.lean` shows that with Lean 4.29.1 and 4.30.0-rc2 a wildcard match over two constructors already brings `propext`, as does `if x matches .a`, while the same match with every constructor written out brings none, and so do matches on `Nat` literals and `n + 1`. A periphery definition could drop `propext` by writing its matches out, as the core's empty reports require of the core. Index bounds and Mathlib's structures would stay. That the core states `↔` where it needs equality of propositions (section 258) is a separate rule, about statements; this one is about how definitions are written.
- **The receipts predate the core.** Every periphery receipt was checked against an earlier core (13 to 19 October). Against the current files, MachineInstances' closure has 34 of its 70 sources changed and 2 gone, CorrectionInquiry's 95 of 113 changed and 4 gone, and only the core receipt matches main. The current `MachineInstances.lean` no longer compiles against the current core (`CrossSituational.Distinct` is unknown). The audit therefore reads each module at its receipt's bytes. It says how the periphery used `propext` when it was checked, not that the periphery checks still pass; renewing them is separate work.

**Self-review.** The classification is only as fine as `Uses.lean`'s lists of eliminators and carriers. Where it was unsure it counted a proof as taken apart, and each such case was then settled by a reduction check or by reading the source, so it errs toward finding a value computed through `propext`, and found none that is the periphery's own. The 14 `Nat.land` definitions and the seven settled by hand or by reduction are statements about Lean 4.29.1 and 4.30.0-rc2 and the pinned Mathlib, not about the theory.
