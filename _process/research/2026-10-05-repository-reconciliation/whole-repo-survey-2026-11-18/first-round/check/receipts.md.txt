## Disagreements settled

1. **Runs named by nothing.** Claude: 6. Astra: 2 (`20261022T044435.181667Z`, `20261106T025121.503688Z`). I reproduced Claude's 6 with the full-stamp regex outside `becoming-checks/`. Searching the 15-character prefix and other runs' receipts as well: 3 of the 6 are named in `_process/research/2026-10-05-repository-reconciliation/whole-repo-review-2026-10-16/review-data.json`, 1 (`20261105T122309`) in the next core receipt `20261105T122637.488502Z/verification.json`. Astra's 2 are right; Claude's 6 is true only for its narrower regex.
2. **What reads the run copies.** Claude: nothing except the 4 Optimum records and about 30 links. Refuted in part: `wisdom-root.json` has two `role: proof` references and two `proof_bindings` whose *source* is a run copy, `BC/20261013T125626.097616Z/Becoming.RegroupingSelection.lean` and `BC/20261013T132140.261612Z/Becoming.RegroupingSelection.lean`. The registry hashes them and reads declarations from them. A third, `LEAN/universal-ethics/generative-capacity/open-future-revision-checks/20261008T131727.086965Z/Controls.lean`, is a proof source of `open-form-realization-under-revision.json`. So 6 records, not 4, rest on copies inside run folders. Astra saw the wisdom-root case.
3. **Is every copied source held elsewhere?** Claude sampled 40 of the 10 November runs and found all 40 in history. Astra found a counterexample, and it holds: blob 2b793e71 (the 13:21 copy) is at one path in the index, and `git log --all --find-object` restricted to the module's own path finds nothing. It is kept in git only at its run path.
4. **Can a kept set resolve every recorded artifact?** Only astra asked this. Confirmed: passed run `20261019T090457.012800Z` (13 files present) lists 740 entries in `artifact_sha256`, 728 missing at their paths, 483 distinct hashes. `BecomingHexagramsAxiomAudit.lean` and `.log` match none of the 29 same-name files in `BC` and are not in `_objects`. Commit 5d32f69f9 says the run "keeps only what main lacks". Not looked at: git history for those bytes.
5. **When run folders became small.** Claude: "since about 11 November". Refuted: `held_in_main` came into `check_becoming.py` in 1a44c1c51 on 12 October, and runs of 5 to 23 files appear from 19 October on. The fat runs after that (up to 1,766 files on 10 November) are runs whose sources were not yet in main. The last fat run is 20261110T144413.
6. **The `.git` share.** Both say about 1–2%. Confirmed. But Claude's "3.9 GB `.git` is mostly `sources/situated-recovery` (about 800 MB)" is refuted. I get 419.1 MB, both by first path and from the current tree, and 419 MB of 3.9 GB is not "mostly". Also seen: objects reachable from all refs and the reflog take 1,748 MB on disk. `git count-objects` reports 1.98 GiB of packs plus 1.53 GiB of loose objects. So about half the object storage is reachable from nothing (inferred from those two counts; the loose objects were not examined).
7. **Counts of `passed_receipts()`.** Claude: 36 scripts. I count 31 live definitions outside history and run folders, and 35 tracked `.py` files outside run folders that call it. Not settled; the scope of "36" is not said.
8. **Smaller astra counts.** Astra: core references 347 files / 344 runs and bindings 105 / 103. I get 348 / 345 and 104 receipts / 104 runs (106 with sources). No record changed between befa506ba and HEAD. These are off by one and unexplained. I count them as not reproduced, not as errors.

## What a decision can rest on now

The receipts (1.68 GB, 550 distinct files) are bound by records and opened by the registry. They cannot move without repointing records. The 64,812 copies beside them are 7,923 contents. The store packed them once, on 17 October, and nothing has packed them since. In `.git` the area is about 2% of reachable storage, so leaving the tree changes checkout size and file count, not repository size. At least 6 records bind or cite copies inside run folders by path, and one bound source exists in the tree at that path only. A record-referenced set is computable (491 paths). Not every recorded artifact can be resolved from today's tree.
