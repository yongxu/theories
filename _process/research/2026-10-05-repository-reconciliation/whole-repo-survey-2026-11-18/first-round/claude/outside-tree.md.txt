# outside-tree: what is there
*AI-written (Claude Opus 5.5), 18 November 2026. A survey; nothing was changed.*

## In three sentences

Outside the tracked tree there are three things: the git store (3.9 GB, of which about 1.45 GB is unreachable loose blobs kept only because nothing prunes), local-only refs that hold about 890 commits main does not (403 salvage refs, 157 branch heads, 2 stashes, none of them on the remote), and scratch (the repository's ignored `tmp/` at 1.7 GB and `/Users/ren/tmp/` at about 45 GB, mostly six landing worktrees). Most of the bulk is machine output or copies, but scratch is not only scratch: live pages, the direction page among them, cite scratch files that are in no git object, and several folders hold readings, Lean drafts and kits found nowhere in git. All of it, and the private folders the `.gitignore` keeps off the remote, exists on this one machine only; I found no working backup.

## What repeats

- `tmp/r7`: of 1,555 `.lean` files only 248 are distinct, and 214 of those are byte-identical to a file on main (counted by `git hash-object` against the index). The rest of r7 repeats itself across round folders (one-model, tt, wu, wu2 and nr each hold a Lean copy; `wu2` and `nr` have no `.md` that is not in git).
- The six landing worktrees in `/Users/ren/tmp` are checkouts of commits in git; none has a modified tracked file. The orphaned `agents-board` has no file outside git.
- `/Users/ren/tmp/ren-words/record.md` (3 November) has its landed form in `sources/15-codex-theory-conversations/2026-11-03-not-my-decision-word-for-word.md` (not byte-identical; 4 of 5 files in that folder are in no git object, the others being scripts).
- Salvage commits repeat work that later landed in rebased form; their 13,489 salvage-only blobs cost 32 MB on disk, because they delta against main.
- The 16 October restructure plan (`_process/research/2026-10-05-repository-reconciliation/whole-repo-review-2026-10-16/RESTRUCTURE-PLAN.md`, lines 239 to 290) counted 88 worktrees (about 228 GB), 142 local branches (131 merged) and 60 `refs/codex` with a 185 MB non-LFS blob, and proposed a cruft-pack gc with never-expire. Now: 7 worktrees, 157 branches (147 merged), 60 codex refs, `gc.pruneexpire never` set, two packs (the large one rewritten 17 Nov 16:03), 47,324 loose objects (1.54 GiB) still there. Its worktree numbers no longer hold; its object-store reading does in kind. I did not check whether its gc was run in the form it proposed.

## What depends on it

- `gate.py` reads `refs/salvage/` to accept record pins to pre-rebase commits (lines 739 to 741, 870 to 878). Removing or moving salvage refs could turn standing pins into gate errors. How many pins name a salvage-only commit: not counted.
- `gate.py` keeps passes in `.git/gate` (line 313); losing them costs a re-run, not content.
- Verification receipts under `experiments/integrated-correction/.../becoming-checks/*/verification.json` record absolute paths in `/Users/ren/tmp/ag`, `ed5`, `lm` (over 1,000 each per file). These are paths of where checks ran, not reads.

## What a continuing session needs from here

It needs the landing worktrees while they are live, the salvage refs while the gate reads them, and `.git/gate` for reuse. It needs the scratch files that live pages lean on, which today it can only reach on this machine: the board's and the direction page's scratch citations, the `tmp/r7/one-model` round files (153 `.md` in no git object) for the one-model line, and the ZA readings. It never opens the unreachable blobs, `refs/codex`, the build outputs in `tmp/r7`, the orphaned `agents-board`, or the gate logs of earlier sessions (`/Users/ren/tmp/*-gate.log`, `*-render.log`, many dozens).

## Candidates

- **Unreachable blobs (1.45 GB):** could leave, but only by a prune, which AGENTS.md forbids; sampled ones are data dumps whose files are likely held elsewhere (not checked). Stays as is unless Ren changes the rule; risk is nil while kept.
- **Salvage refs and unmerged branches:** stay. They are the only copy of 890 commits, are on no remote, and the gate reads them. Before any change: count pins that name salvage-only commits; decide whether to push them to a private ref namespace on the remote.
- **Stashes:** stay, or salvage to `refs/salvage/` (they are the only refs that a `git stash drop` could lose; 15 stashed file versions are not in main's history).
- **`refs/codex`, `.git/gate`, `tmp/r7` build outputs, `agents-board`:** machine output, regenerable or fully in git; could go without loss, `agents-board` by name after `git worktree` metadata is checked. Whose sessions use them: not determined.
- **Scratch cited by live pages:** cannot stay as it is if the repository alone must carry the work (brief item 5). Either the cited files enter the tree (a study folder) or the citations change. What would change first: a sweep of tracked citations into scratch, then per file a decision.
- **Scratch kits, logs and readings in `/Users/ren/tmp`:** cannot tell from 13 of 219. Many hold files in no git object; most look like kits and logs (trace whose result landed), some like readings (ZA, AG). Needs a per-folder pass before anything moves.
- **Private folders and `experiments/guardian-anarchy`:** stay off the remote by Ren's rule; they need a backup that is not this machine.

## Against the two views

- Against "much is garbage": almost nothing here is a telling to compress; most is trace or machine output, and the bulk (unreachable blobs, worktrees) costs disk, not reading. Removing it would not make the map more joined.
- Against "trace and machine output can leave the reading path without loss": that is mostly so for git, but not for scratch. Live pages and the direction page already rest on files outside the tree, so the reading path itself leaks out of the repository. And the salvage refs, the only copy of 890 commits, are not on the remote, so "git history keeps whatever leaves the working tree" holds only on this machine.
- The layout rule's "nothing is deleted" is kept in git (pruneexpire never, salvage before removal), but not in scratch: `/private/tmp` loses unread files after about three days (RESULT-WORKFLOW), and `/Users/ren/tmp` is not tracked anywhere.

## Not determined, and surprises

- Surprises: the direction page's own head note leans on scratch; an orphaned 874 MB worktree; 1.45 GB of unreachable loose objects despite the 16 October gc plan; `ue31-design` carries 4,091 lines not on main, from 3 November; `ren-words` in scratch is a kit, not Ren's words.
- Direction: the AGENTS.md line "what the repository cannot regenerate stays" is carried by the git practice, and contradicted in effect by where the latest readings and corrections are kept.

git for-each-ref --format='%(refname)' | awk -F/ '{print $1"/"$2}' | sort | uniq -c
