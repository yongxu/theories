# 数据与关系

这个项目用具体语境中的义项和完整判断组织思想材料。单字是检索入口；真正被比较和连接的是某一段文本中某一用法，不是一个脱离语境的汉字。

| 对象 | 主要内容 | 不代表什么 |
|---|---|---|
| `nodes` | 词义、状态、操作；定义、认知功能、来源与限制 | 不自动等于跨流派通用概念 |
| `relations` | 完整前后项、条件方式、动词、层次与证据 | 不自动是现代经验因果 |
| `reading_units` 等原文数组 | 全文或连续选段、实际阅读状态、正反向映射 | 取得全文不等于已经读完或穷尽思想 |
| `interactions` | 某作者引用、批评、解释或会通其他文本的行为 | 不把作者对他者的描述当作他者定论 |
| `comparisons` | 现代提出的问题，两侧以上的完整论证、异同与不可等同处 | 不证明历史传播或概念同一 |
| `systems` | 可追踪的阅读路线 | 路线邻接不表示原典推论 |
| `sources` | URL、版本、冻结文本和原始响应哈希 | 哈希保证文件身份，不保证底本无误 |
| `coverage` / `bibliography_backlog` | 有限处理范围、未处理文献与问题 | 不是对绝对全集的证明 |

每条新证据包含 `source_id`、连续 `quote`、`locator`、真实 `unit`。验证只忽略空白，不把繁简替换、拼接或现代改写当作同一引文。电子转录与其底本、语言显示转换与独立版本见证也分开。

`premise_mode=all` 表示共同前提，`any` 表示备选前提，`individual` 表示明确的逐项关系；不能用一个合并节点掩盖实际上一一对应的多个判断。多前提箭头必须经过断言节点，不能把每一前提都误看作足够条件。否定和模态须同时在节点、动词、claim 与原文中读通。

例如，《解老》把“行端直→无祸害→尽天年→全而寿”与“得事理→必成功→富与贵”分别展开，再用全寿富贵释福。项目保留这些中介；原作者的强断言仍被标明为其解释，不因此变成现实世界的保证。

同一组材料可以有多条导航路径：传统、文本、明确署名、主题、词形、年代、现代问题。导航可以重叠，但不改写原始语境。无法确定的年代留在未定位部分，不由篇名和传统题署猜出年份。

`data/graph.json` 是完整判断超图；`multilayer_graph.json` 包含所有注册记录与明确关联，并为每条边标注层次。`topology_index.json` 记录全部语义关联分量；`lexical_index.json` 保留单字义项与完整词形双索引。JSON 和 GraphML 保留完整记录，SQLite 提供查询入口。具体字段及构建行为以冻结工具和规范模型为准。

本代继承前代全部注册记录的字段。新增记录带本轮输入包哈希和生成代标识；父代工具、模型与证据可在本项目内离线复验。这样可以追查某项判断在何时、据什么原文、以何种解释进入项目。
