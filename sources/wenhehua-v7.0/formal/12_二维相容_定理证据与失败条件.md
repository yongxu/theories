# 二维相容：定理、实例与必要边界

## I. 数学定理来自何处

目标不是原创地“证明二胞交换律”，而是**在合适的对象类中引用并实现既有的数学构造**。对于一个拓扑斯 `T`，Cicala（2018）及 Cicala–Courser（2018）证明了以对象为 0-胞、余跨度为 1-胞、单态跨度的同构类为 2-胞的双范畴，其中横向连接采用推积，纵向接续采用拉回，满足二胞交换相容律。双范畴具有对称幺半结构。Cicala（2026）进一步研究了结构化余跨度重写及其 2-范畴语言。

本研究的**专属部分**是中文生成文法的概念阐释、有限子类的具体可执行规格、接口条件和行为反例；不是这些数学定理的首创。

## II. 直观证明框架

设 `α:A₀⇒A₁`、`γ:A₁⇒A₂`，`β:B₀⇒B₁`、`δ:B₁⇒B₂`。我们有两条复合路径：

\[
\mathrm{Path}_1=(\gamma\cdot\alpha)\odot(\delta\cdot\beta),
\quad
\mathrm{Path}_2=(\gamma\odot\delta)\cdot(\alpha\odot\beta).
\]

两条路径的源、靶外界面相同。前者先在左右两侧各用拉回提取跨两次变化的保存部分，再将其沿共界推积；后者先在每一个时间层上水平粘合，后对两个层间的保存部分拉回。对于适当黏合的图范畴及单态条件，所得保存部分存在典范同构，且与两端网络的单态嵌入相容。这一事实必须在相关范畴定理的前提下使用。

不能只根据两条路径的“节点数相同”就推出交换律；必须提供节点、边、端口以及保留映射都相容的同构。v2.0 软件的 `isomorphic_witness` 专门在固定外部图标识条件下检查这些对应，避免只比较最终拓扑。

## III. 有限实例中具体发生了什么

两个网络 `A`、`B` 各自是一条有向边 `in → out`，经 `A.out = B.in` 连接为一条链。第一轮：`A` 和 `B` 各自增加一个内部标记节点及关联；第二轮又各自增加一个新的内部标记节点及关联。外部接口始终保留。

将第一轮的二胞记为 `α, β`，第二轮的二胞记为 `γ, δ`。运行：

```bash
cd software
PYTHONPATH=. python demo_higher.py
```

得到：

```text
Interchange square (fixed boundary, monic spans): True
Two-stage preserved vertices: 3
After-gluing nodes: 7
Associativity up to boundary-aware graph isomorphism: True
```

第二种实例允许删除不触及外部界面的内部边，也能通过相应的交换检验。`True` 是有限受限实例的检验结果，不是一般定理的形式证明。

## IV. 不能省略的前提

1. 两侧连接的界面类型相容。
2. 单次重写的边界得以保存，保留跨度两腿必须单态。
3. 纵向合成具有相同的中间一胞，或提供明确的中间同构/transport。
4. 各构造发生在支持相关推积/拉回并满足定理前提的范畴。
5. 不把任意行为语义错误地推入纯结构层。
6. 若要求“变化本身具有局部规则许可证”，必须另核对 DPO 匹配及悬挂条件；纯二胞存在不足以担保这一点。

## V. 失败实例

**类型失配**：`A.out` 为 `Node`，`B.in` 为 `Resource`，水平拼接被拒绝。

**边界删除**：二胞共同部分不含外部端口所对应节点，改变被拒绝。

**非单态**：两项不同的保留节点映到同一节点，违反单态要求，被拒绝。

**不同中间态**：纵向变更的后一轮前态不是前一轮后态，未显式给出同构迁移，程序拒绝。

**全局不变量失效**：两个网络分别满足入度 ≤ 1，但共同接口的识别可能增加入度，不能从局部性质无条件推出整体性质。

**行为保真失效**：二胞合法地删除唯一有向路径上的一条边，造成可达性由真变假。说明「改变」与「行为等价」不是一回事。

**粗粒化失效**：沿用 v1.2 的 `compatible_abstraction` 与 `strong_lumpability`，若宏观纤维内部微观动力学不一致，不存在相应的闭合宏观动力学。高阶组合本身不会修复这个问题。

## VI. 为什么这些反例是研究结果，而不是瑕疵

它们回答了更精确的问题：什么样的组合/变化在何种条件下成立？任何希望用于软件、机器人、生物和制度的形式语言，都必须有清楚的拒绝机制。没有失败条件的“普适”往往只是把矛盾隐藏在解释中。

## VII. 后续需要更高阶的东西

固定外界面的二胞已经完成一个严谨的统一核心；但若要重写接口本身，必须把纵向外界映射也纳入模型。适当的 **double category**、**equipment**、**polynomial functors** 或有依赖类型的接口迁移语义可能是发展方向，不能把其成熟性等同于现有的 `Change` 程序。
