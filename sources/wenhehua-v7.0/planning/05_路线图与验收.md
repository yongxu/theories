**不是空白计划：表格同时记录本轮交付状态。** 本轮已将研究基准做成文件和可运行原型；未来课题另列，不用将长期开放问题误写为已完成。

## 1. 总目标

建立一种以尽量少的独立构造表示开放、可变、可组合系统的语言：同时维持人类理解的自然性、结构操作的严格性、领域语义的可替换性与证据的可追溯性。

## 3. 长期研究计划（按依赖顺序）

### 研究一：形式语言与数学对照

- 比较自由对称幺半范畴、operad、structured cospan、双范畴/高阶重写，明确相同和不同的表达能力。
- 给出完整的类别、函子和两个操作的保结构解释。
- 完成 P1/P2 的机器辅助形式验证或独立数学审稿。
- 构建通用匹配算法及临界对冲突检测。

验收：形式定义可被外部数学家逐步核对；不再依赖只选好的例子。

### 研究二：多领域语义后端

- 定义并实现可检查的离散状态机、随机核、Petri 反应网络、连续/混合动力学语义接口。
- 为物理资源加入单位、守恒、可复制性和时间约束。
- 将具体图与方程、实验数据对齐并记录误差。

验收：相同组成图在至少三种有差异的语义后端中明确解释，并能指出各自不保的性质。

### 研究三：变化中的接口与规则

- 开放图式及状态之间的依赖类型；重构时的状态迁移。
- 规则版本化与有条件的元重写。
- 对自主智能体建立权限边界和外部可信验证层。

验收：用户可构造能修改自己内部图式的系统，并能检查接口与资源安全条件；不宣称证明其全部行为安全。

### 研究四：跨尺度抽象

- 精确与近似的动态交换图。
- 因果干预查询的保持条件。
- 多尺度模型的一致性反例库。

验收：对两种有具体数据的模型给出能保留和不能保留的查询清单。

### 研究五：词法与认知实验

- 对「文、合、化」与国际术语做双语术语设计。
- 分别邀请数学、工程、生态、社会科学读者按盲测任务表达同一系统。
- 评估定义理解正确率、表达长度、排错能力和错误迁移率。

验收：从真实任务证明一种词法更有利于理解，而不是依赖作者的主观偏好。

### 研究六：软件、机器人、协作系统应用

- 用同一个构造中间表示描述模块化硬件和组合软件。
- 建立机器可检查的合同、资源流程及模型版本历史。
- 在社区协作研究中表达规则与参与者，但保持社会正当性为独立评价。

验收：至少一个真实应用成功使用可组合构造和不变量检查；第三方能够复现。

## 4. 研究中最有价值的否定性成果

如果「文、合、化」不能更经济地表达某些领域，或一个更简单的系统经实测更优，应公开替代当前版本。如果一种跨尺度抽象无法保持因果查询，应保留反例。如果一个古语词义不符历史证据，应明确改称项目造词。

这样的失败不意味着研究无价值；它告诉我们普适性的适用边界。理论的质量是其能否清楚处理不成立的情形。

## 5. 实施规范

每一次正式升级建议同时改动：`定义 → 用例 → 反例 → 测试 → 文献 → 词库 → 版本日志`。增加新的「文」系词条时，应写明其生成规则与是否真的区别于已存在的概念。

当研究涉及多代理或并行开发时，按主题分工而非大量重复生成：数学定义、语词考据、工程实现、批判性测试四组，集中集成与交叉审查。**本版没有实际启动独立子代理；上述只是明确的协作设计。**
