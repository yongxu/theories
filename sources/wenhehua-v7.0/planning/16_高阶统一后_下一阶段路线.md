# v2.0 之后：高阶统一到普适语义的研究路线

## 已经完成的里程碑

- **M0**：确定「文—合—化—则—观」概念架构，并区分本原、操作、语义与检验。
- **M1**：找到已被数学文献证明的「合与化」共同高阶结构：monic spans of cospans bicategory。
- **M2**：给出固定边界、有限类型化网络的明确形式规格和 Python 构造，包括 pushout、pullback、2-cell horizontal pasting。
- **M3**：给出一个被测试的二维 interchange 实例、弱结合/单位律实例、非法构造与不保真反例。
- **M4**：把术语、数学与软件实现范围统一到一份可读、可追溯、可运行的工程研究包。

## 真正仍需继续的工作（不应假装完成）

### P1 · 数学结构层（最高优先）

把当前固定接口片段升级为具有接口更替（含生成、撤除、重命名、依赖类型变化）的 double-category / equipment 风格结构。需要区分：外界箭头、内部改变、以及方格兼容性。

**验收：**提出严格对象/一胞/二胞定义；给出无歧义的自然性和相容条件；至少证明一条不平凡的接口更替相容命题并给出边界破坏反例。

### P2 · 形式证明层

在 Lean 4 或 Agda/Rocq 中形式化有限有类型开放图、单态映射、推积和拉回。优先证明核心函数与数学规范一致，再扩展至 interchange 的有限实例或使用成熟库。

**验收：**编译成功的定理文件；无未解释的 `sorry`/未验证占位；与 Python 生成的有限实例交叉检查。

### P3 · 语义解释层

加入至少两个完全不同且可组合的语义：例如 Petri 资源流与有限概率过程。明确哪些二胞保存哪些性质，哪些只表示允许的重构。对于连续系统与量纲、几何、因果干预，须另置具体公理。

**验收：**每一个语义都提供对象解释、复合保持、二胞解释、错误条件、至少一条验证命题及反例。

### P4 · 更高阶的「文之文」

把规则或编排本身作为合法结构，使某些元规则能够有类型地修改规则。必须研究不同反身层级的许可、终止性、合流性与安全限制。不得因为“规则也是数据”就认为任何自修改都有可信意义。

**验收：**支持至少一个有限有界的元重写例子，同时能拒绝违反类型或越权改变接口的反例。

### P5 · 跨域验证

分别在软件服务、模块机器人、生态网络和机构协作中寻找共同的构造结构，但用各自领域模型验证语义忠实度。制度与规范价值需独立指定评价与参与者权利的检验框架。

**验收：**每个领域至少有一个工作范例和一个该框架无法无损表达的反例；可复现实验与独立审查记录。

## 研究评价表

比较任何“一操作”“二操作”“三字”候选体系时，应将词法长度之外的隐含类型前提、非法表达比例、推理步数、证明负担、编译代价和人类理解误差一并记录。不能只凭字符数或术语美感宣称最小。

**最终科学目标**不是一个永远没有失败条件的“万物定理”，而是一个可逐渐增加语义、保持组合结构、明确说明何处有损的开放生成文法。
