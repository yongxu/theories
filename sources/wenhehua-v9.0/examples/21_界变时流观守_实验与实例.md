# 第三阶段实验：从改变接口到检查宏观意义

## 1. 复现环境

本版只使用 Python 标准库（`unittest`、`dataclasses`、`fractions` 等）。从项目目录运行：

```bash
cd software
PYTHONPATH=. python -m unittest discover -s tests -v
PYTHONPATH=. python demo_v3.py
```

输出以 `evidence/tests_v3.0.txt` 和 `evidence/demo_v3.0.txt` 为准；本次运行得到 **94 tests, OK**，其中包括 v1.2、v2.0 全套回归测试及新接口/概率/流量/模式机测试。测试只证明这些有限输入的实现行为，不构成一般范畴理论的机器化证明。

## 2. 实验一：外界改变而接缝稳定

- 左组件 $A_0$ 有一输入、一输出，之后增加第二个输入；
- 右组件 $B_0$ 有一输入、一输出，之后增加第二个输出；
- 两者共享的左输出—右输入端口不变，身份迹均为 `(0→0)`；
- 先粘合 $A_0,B_0$，又粘合 $A_1,B_1$；两边共同保留子图也沿原接缝粘合。

实际输出：

```text
[界变] left interfaces: 1 -> 2
[界变] right interfaces: 1 -> 2
[界变] common graph nodes: 3
```

因此我们不再需要声称「外部界必须静止」，也能在一类安全条件下保留 v2.0 的横向相成机制。

**失败例**：当共享接缝增加新端口而另一侧未同步升级，`horizontal_evolution` 会拒绝，而不是猜测该把新端口接到哪里。若两侧都改变，但没有明确且完整的接缝身份迹，也拒绝。

## 3. 实验二：接口的名字与身份不同

某设备先有 `out:0` 与 `out:1`。撤去 `out:1` 后，又重新建立一个也叫 `out:1` 的端口。

现象上二者同名；但持续身份只存在于 `out:0`。两次部分迹合成后，`out:1` 没有从最初阶段持续到最后阶段的轨迹。

这是对「同」的具体修订：**名称复现并不证明身份延续**。对真实设备还可能要求硬件序列、物理轨迹或权限移交等更强见证；本原型只检查声明的结构性持续身份。

## 4. 实验三：有限模式机与传感器损坏

健康模式：输出温度、湿度；输入动作可以是 `tick`、`damage`。损坏模式：只输出温度；输入动作可以是 `tick`、`repair`。

```text
[时流] after damage: (('damaged', (('temp', '20'), ('humidity', '50'))),)
[时流] damaged next output: (('damaged', (('temp', '20'),)),)
```

注意：一次触发损坏的事件仍按**当时健康模式**输出两个值，下一轮才采用新的界面。模型记录了明确时序，因此没有「损坏瞬间是否仍要输出湿度」的模糊空间。若要在一个事件内部改变接口，则需更细粒度事件语义。

**失效**：损坏模式收到 `damage` 动作，或输出两个值，都会因当前接口不相容而被拒绝。

## 5. 实验四：概率组合与精确粗粒化

概率核 `Kernel(X,Y,K)` 的每行概率合计必须为 1。我们支持：

- 顺序组合：对中间态求和；
- 在指定独立性假设下并行张量：概率相乘；
- 有限马尔可夫链的强可聚合性检查：同块微状态到各目标块的概率合计必须一致。

成功例中，微状态 0、1 属于宏观 A，2 属于宏观 B；0、1 的内部迁移细节允许不同，只要它们去往宏观 A/B 的概率合计相同。宏观链是良定义的。

失败例：0 总留在 A，1 总去 B，却把二者都映射到 A。宏观更新将依赖不可见的微状态，故拒绝。

## 6. 实验五：同宏观状态不应掩盖不同接口

即便宏观状态转移概率可以聚合，状态 0 暴露温度，状态 1 暴露温度+湿度，仍然不能在**严格保持接口**的语义下把两者视为同一个宏观状态。

```text
[反例] rejected abstract interface: interface abstraction conflict: 0 vs 1
```

若研究任务只询问温度，可以定义新的观察映射，显式舍弃湿度差异；但那是另一种、有损的抽象，不能冒称原接口保留。

## 7. 实验六：连续时间储量流

两个储量节点 $A,B$，内部通量 $q=kx_A$，外部输入 $u$ 加到 A，外部输出 $c x_B$ 从 B 离开，则

\[
\dot x_A=u-kx_A,\qquad \dot x_B=kx_A-cx_B,
\]
\[
\dot x_A+\dot x_B=u-cx_B.
\]

以 $x_A=4, x_B=6, k=\tfrac12,c=\tfrac13,u=3$：

```text
[守恒] dx/dt: {'tank1': Fraction(1, 1), 'tank2': Fraction(0, 1)} boundary balance: 1 verified: True
```

我们的程序检查的是瞬时收支恒等式；它没有求解 ODE，没有建模热力学耗散或系统结构改变时的连续边界迁移。

## 8. 跨域映射：共通文法与不可跨越的语义区别

| 场景 | 文 | 合 | 化 | 界变 | 必须另验 |
|---|---|---|---|---|---|
| 软件 | 服务网络 | API 连接 | 模块替换 | 热插拔端点 | 协议语义、权限、安全 |
| 机器人 | 传感执行网络 | 接口耦合 | 机械重构 | 端口增减 | 受力、几何、能量 |
| 生态 | 营养/作用网络 | 物种/物质通路 | 群落演替 | 交换路径改变 | 实测参数、守恒、尺度 |
| 团体 | 协作程序图 | 共同协议 | 程序修订 | 参与入口变化 | 同意、权利、合法性、福利 |

共同的是**构造和检验框架**；绝不可认为这些世界具有完全相同的细节方程、时间尺度或规范标准。

## 9. 用户实际可做的复核

可直接打开并运行 `software/demo_v3.py`，修改概率行、改变端口映射、删去持续身份，观察框架如何拒绝错误构造；再把自己的系统（例如一个可重构机器的传感与供电模块）编码为 typed graph 和 mode machine。每一步应附上「哪些量被保留、哪些意义被放弃」的模型说明。
