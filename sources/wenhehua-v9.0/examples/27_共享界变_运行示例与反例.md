# 实验 C：公共接缝的生、退、并、分与调适

## C0. 复现环境

```bash
cd software
PYTHONPATH=. python -m unittest discover -s tests -v
PYTHONPATH=. python demo_v4.py
```

不依赖网络，核心运行时只用 Python 标准库。程序从 v3 的 94 项回归测试扩展到 **115 项测试**，其中新增加的 21 项检验共享界变化与显式适配；由于测试来自有限实例，不能当作数学上的完全性证明。

## C1. 在保留旧接缝时增加一条新通道

旧时 $J_0=(N)$，新时 $J_1=(N,T)$。旧 $N$ 类型通道持续，新增 $T$ 类型通道不在两侧旧共同见证中出现：

$$
\tau=\{0\mapsto0\}: (N)\rightharpoonup(N,T).
$$

两侧图分别各保留两个节点，连接旧时总节点数 3；新时新增两个节点，但沿新接缝多识别一个，故新时总节点数 4。共同见证含 3 个节点。程序运行证实：

```json
{
  "old_seam_arity": 1,
  "new_seam_arity": 2,
  "old_joint_nodes": 3,
  "new_joint_nodes": 4,
  "persistent_joint_nodes": 3,
  "claims": {
    "structural_witness_checked": true,
    "resource_conservation_proven": false,
    "behavioral_equivalence_proven": false
  }
}
```

注意：新增通道不一定代表新增实体，只代表旧界面未将该通道暴露；这里的 demo 为方便阅读，恰好选择添加全新节点。

## C2. 撤回一个已经存在的共享端口

由 $J_0=(N,T)$ 退为 $J_1=(N)$，同样取 $\tau=\{0\mapsto0\}$。如果新旧共同见证均**不承诺**撤回的 $T$ 通道之身份，候选整体共同见证可严格嵌入旧新整体，直接成功。

如果两侧还分别将该旧 $T$ 节点当作持续的局部节点，且旧阶段整个系统已经把它们识别在一起，但新阶段又将它们分开，那么不可能一边要求两条映射单射，一边保留两份冲突身份断言。这时严格模式会拒绝。

## C3. 临时并界：为什么两份合法身份主张不能自动相合

旧时两侧各有私人节点 $a,b$，它们不相接；新时双方都将它们暴露为共用端口，新整体通过推积把两端识别为一个节点。

局部看，$a$ 与 $b$ 各自都仍存在，局部变化见证分别合法。

但全局看，若共同见证中 $a,b$ 仍是两个节点，那么新整体中它们同像：

$$
\iota_1(a)=\iota_1(b),\qquad a\ne b.
$$

这使 $\iota_1$ 不是单态。`policy='strict'` 以 `GrammarError` 拒绝；`policy='forget_conflicts'` 明确从共同见证中同时撤回这些身份断言，再重新检查所需外部接口是否得到保留。

这不是宣布两个物体物理上毁灭了，而是避免把“局部身份持续”强行误用成“整体身份始终两两不同”。

## C4. 临时分界：谁继承旧共享身份？

同理，旧时两侧通过一个端口相合，撤回这个端口后成为两个局部节点。局部两侧仍可指向各自的连续节点，但全局旧网络中原本只有一个共享点。若强行将两份局部身份都记为同一旧身份的单态延续，会在 $\iota_0$ 遇到碰并。

图文语言应将此区分为：**连接关系解除**、**节点身份是否连续**、**原有量或功能如何分配**。它们分别需要结构见证、身份语义与资源／行为语义。

## C5. 强制持续的外部身份不能被弱化掩盖

如果冲突的内部节点恰好还是被外部 `InterfaceTrace` 明确承诺持续的端口，那么删除它们会破坏外部接口因子化条件。此时即便选择 `forget_conflicts`，程序也必须拒绝，而不能把未经证明的“重新连接成功”返回为合法结果。

该行为由 `test_forget_cannot_break_outer_trace` 检验。

## C6. 明示复制与合并的调适器

假设 $A$ 提供一个 $N$ 类型输出，$B$ 需要两个 $N$ 类型输入。直接组合因接口数量不一致而失败。

可显式声明某个生成元：

$$
\mathrm{copy}_N:N\longrightarrow N\otimes N.
$$

并以其作为中间开放图，再作两次合法接口连接：

$$
A \longrightarrow M_{\mathrm{copy}}\longrightarrow B.
$$

同理，$N\otimes N\to N$ 可以表示明确的合流生成元；$N\to X$ 可以表示有声明的类型转换生成元。但这只解决**类型化语法**，还不能证明复制一个数值、物质资源、权限或未知量子态在领域语义上合法。

在量化语义里，复制或丢弃往往需要相应的代数（如 comonoid），或者应当被禁止。`test_no_conservation_is_inferred` 明确将这种非保证列为检查对象。

## C7. 重要负例：弱化不保持任意两方向合成

构造三阶段：

$$
\text{分离}\quad\longrightarrow\quad\text{临时连接}\quad\longrightarrow\quad\text{分离}.
$$

两侧局部系统的私人节点贯穿三阶段；但在中间的全局连接中，两个节点在推积下被识别。

- **先逐阶段合成再接续**：两个阶段均需弱化碰并身份，最后共同见证仅保留 2 个外部节点。
- **先各自接续局部变化，再在首末两态合成**：首末都无共享接缝，仍可保留 4 个共同节点。

因此两条路径的共同见证强度不同。

`test_transient_fusion_and_fission_loses_identity_information` 给出可以重复执行的有限反例。它表明：**保守合法性与高阶自然性是不同要求**。已有的 spans-of-cospans 交换定理是在相应的固定对象与严格定义的二胞条件下成立；我们不能将其无条件迁移给一个带有任意择定弱化策略的编程接口。

## C8. 程序边界

- 仅有限有类型节点及超边，且仅按离散端口粘合节点；
- 改变中的内图保留仍由单态跨度表示；
- 一个共同见证的 node/edge ID 在本实现中是局部程序标识，非通用本体论身份；
- 对外接合仅要求结构正确，任何概率、物理、延迟、权限、制度意义必须另加模型；
- 当前没有最小冲突核搜索、所有可能修复的枚举、可验证的最优保持策略，也没有形式化证明助手的完整证明。
