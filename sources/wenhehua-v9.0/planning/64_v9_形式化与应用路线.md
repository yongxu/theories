# 从已完成构造到可用于工程的形式系统

## 1. 本版已经可以做什么

现在可以声明双向接口和生成事件，构造有完整边界的方胞，检查明确的结构相等证书，记录有方向的局部变化，组合与运输三维原始项，并运行有限动态图式的装配与历史比较。对不同装配时机，程序能显示漏掉的整体历史和被合并的局部历史。

下一阶段不必再次更换整个哲学词汇。应沿已有接口逐项加强可验证性、可用性和领域语义。

## 2. 第一优先级：建立证明助手中的小可信核

选择 Lean、Rocq 或 Agda 中一种实际可构建的环境，固定版本和依赖。先形式化有限带类型路径与四边界，继而定义原始二维项和结构等式证书的归纳类型。第一个验收目标是：每个合法证书在任意满足公理的模型中可靠。

随后形式化相对三维项的源靶保持与低维保守性。独立形式化“任意函子诱导跨度比较”的投影证明，以及三步相干再到任意有限链的归纳。此处应直接形式化全称命题，不用遍历很多有限例子替代。

**验收物：**可重复编译的源码、编译日志、无未填证明占位的定理清单、与本文变量及方向逐项一致的对照表。本版运行环境没有现成证明助手，因此没有把未执行的脚本作为已核验文件交付。

## 3. 第二优先级：让等式证书可由算法生成

当前内核只检查给定证书，不替用户搜寻所有证明。无额外关系的自由双范畴已有判等算法，可按 Delpeuch 的构造实现，并使算法输出可由现有小核检查的证书。[S3]

若引入领域等式 $R_2$，先明确是否仍要判等、仅要寻找重写，或要证明某个方向的优化。若使用规范化，必须另证终止与合流，或明确失败/未知的情况。不要把“没有找到证书”当成不相等。

**验收物：**一组明确可判定的输入语言、生成证书的算法、复杂度说明、错误与未知结果的区分、与小核独立的验证路径。

## 4. 第三优先级：完成一个可测领域的闭环

建议先选有限确定性软件管线，或有限状态的可重构连接系统。这两个场景可以提供明确边界、有限语义和可计算的行为关系。

以软件管线为例，接口携带输入输出类型、效果与资源使用；生成元对应具体函数或状态转移；变化规则对应重构或优化；观察可选择输出、错误、成本及状态轨迹。每条优化应证明指定观察保持，或给出允许的细化关系与误差界。

以可重构构件为例，接口携带连接类型、方向和状态；接缝是明确的接口对应；历史见证记录实际允许的延续；临时共界带来的新路径应显式出现。动力学、负载与能量约束应成为领域模型的一部分，不能只靠拓扑连通性证明结构可用。

**验收物：**同一份生成描述能同时产出执行模型、检查证书和反例；给出至少一个合法组合、一个非法接口、一个不保行为变化、一个观测不足例。

## 5. 第四优先级：把并排与变形状接入实现

形式卷 66 已给出有限带类型集合中的对称幺半并排结构，以及它与时间合成、$Q$ 和 $\chi$ 的相容证明。下一步实现显式标签的不交并、置换与分配同构，再把语法侧的幺半呈示连接到这套目标。

形式卷 60 给出 $\mathsf{Diag}_{fin}(\mathcal C)$ 的可变形状构造。实现时需要明确有限范畴、形状函子、自然变换和严格拉回。一般图的自由路径范畴可能无限，不能用有限箭头表假装已经覆盖。

**验收物：**形状映射可检查、跨版本有稳定的结构标识、变形状历史能保留原接缝见证，并输出实际比较及其单满射状态。

## 6. 第五优先级：有需要时进入更广的高阶弱结构

若实际案例要求装配本身与变化一起成为内部方向，而不是一个外部聚合函子，便进一步选择 intercategory 或另一种弱多重结构。先列出所需对象、三类箭头、面、立方体和单位，再逐项验证文献公理。[S5]

验收标准应是一个具体解释定理或一个明确反例，而非把所有组件装入一个新名称。严格核和已有余松模块仍可复用，但不能未经证明地宣布二者自动形成完整的弱高阶整体。

## 7. 可直接复现的入口

在软件目录运行：

```bash
python3 demo_v9_kernel.py
python3 demo_v9_semantics.py
python3 -m unittest discover -s tests -v
```

前两个新示例只需 Python 标准库。全套历史测试还需要 `networkx`，依赖文件保留在软件目录；本版验证用的具体版本见证据报告。源码、结果 JSON、测试日志及构建脚本均包含在总包内。

最有价值的下一版本应将上述某一验收闭环真正做实；不应只增加一个版本号或更多抽象名词。
