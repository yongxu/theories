# 审查 D：可以成立、不能声称、仍然待证

## D1. 本次解决了什么

v3 的稳定接缝限制是一个**可执行层面的阻碍**：过去只有接缝整体身份完整持续时，两侧局部变化才能水平合成。v4 提供了一个受限但清楚的替代：允许接缝增删，并把仅有一部分接缝身份持续的情况纳入严格候选见证检验。

这是一项**模型与程序能力的扩展**，而非宣称跨越所有系统的最终统一完成。

## D2. 最关键的逻辑漏洞，以及如何处理

### 漏洞 1：只要两侧的端口变化一致，便能拼出单态见证？

**不能。** 两侧局部共同见证即使各自完全合法，在整体推积中也可能被识别到同一旧节点或同一新节点。严格模式会检验两个诱导映射的单射性；任何一侧失败都拒绝。

### 漏洞 2：同名、同型或被同一连接所指，能否证明身份延续？

**不能。** `InterfaceTrace` 显式记录持久位置，且具体的共同子图提供双态见证。若两阶段只具有同型节点，却没有见证，系统不宣称延续。

### 漏洞 3：删除冲突见证后就得到最自然的相合？

**不能。** `forget_conflicts` 是保守的、信息损失的构造，甚至不保证是最大的合法共同子图。它对于“暂合又分”存在不可交换的反例。它只保证在重复校验后**返回的结果在当前模型中合法**。

### 漏洞 4：把复制、合并操作写成一种边，就具备资源合法性？

**不能。** `junction` 只是从显式签名建立某个生成元。它不自动赋予其守恒、单位转换、权限分配或量子合法性的含义。需要用适当的语义函子或验证器检查额外公理。

### 漏洞 5：两个局部系统都能变界，是否已有一般的动态双范畴？

**尚无。** 目前实现的是有限对象上的带迹更改及一个**部分定义**的水平操作。尤其是弱化策略不可任意互换，既不能宣称生成了一般的 equipment，也不能宣称它和 polynomial trees 等价。

### 漏洞 6：保留结构就保留行为？

**不能。** 图的可达性、随机核、连续流、因果关系可以分别具有不同的保真条件。v3 已给出若干例子，v4 不把它们混入单态跨度的基本结论。

## D3. 结论强度标注

| 陈述 | 最多可用的结论词 |
|---|---|
| 有限 typed graph 的接缝新生与撤回 | **已实现并经测试** |
| 单态候选见证的精确判据 | **在指定模型下有简短证明** |
| 共同见证碰并的严格拒绝 | **可构造反例、程序可复现** |
| 冲突弱化后可能仍有合法见证 | **有条件成立，非自然优化** |
| 弱化导致 interchange 失败 | **有明确反例** |
| 明示生成元可连接不同数量的接口 | **语法已实现，领域语义未证明** |
| 一般动态共界的完整高阶理论 | **开放研究问题** |
| 普适最小生成文法 | **尚无最小性与完备性定理** |

## D4. 最小反例集合

1. **碰并**：两个不同的旧私人身份，在新整体推积中被识别；新诱导映射非单射。
2. **分裂**：一个旧共享节点在新整体中分开，两个局部共同见证都指向同一旧整体节点；旧诱导映射非单射。
3. **外缘拒弱**：某个碰并点同时承诺外部持续身份；弱化会破坏界面因子化，因此必须拒绝。
4. **类型不合**：两侧的接缝元素个数可以一致，类型却不同；直接连接拒绝。
5. **复制非免费**：一个生成元在语法上可以写为 $1\to 2$，但若语义是独占资源，它未必有合法解释。
6. **非自然弱化**：同一首末配置下，“先阶段合成”和“先局部垂直接续”保留的共同身份不同。
7. **语义缺失**：单态共同见证可以成立，但程序性质、物理守恒、因果结果仍可变化。

## D5. 独立审查应如何推翻我们的结论

建议让外部审稿或证明助手优先尝试以下挑战：

- 找到满足 B1–B3、两条诱导 leg 均单射，且外部因子化成立，但返回 `Evolution.check` 失败的反例；
- 找到在 `forget_conflicts` 之后仍有节点碰并、悬挂超边或持续外界丢失而程序未拒绝的反例；
- 证明或否定一个比“全部冲突见证同时删除”更强、且在限定对象类中**自然**的保持策略；
- 在给定有向 typed hypergraph 的 pushout/pullback 形式中，明确写出当 interface occurrences 可以共享内部节点时的所有必要条件；
- 找到 `SeamContract` 对外部接口与双态共同见证的隐藏一致性漏洞；
- 为产生复制、合并的介面适配器补上与资源语义、线性类型及权限模型的相容性检查。

在这些挑战被解决之前，版本号 4.0 只是研究工程里程碑，不是公理系统已完备的标志。
