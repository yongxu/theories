# 八字十三边：可执行规则案例 v0.4

这里验证的是一张有类型概念图在公开现代模型中的条件推演。每条原始无向邻接都有一个成功实例，以及一个针对**无条件邻接推论或删去必要前提后保证**的失败例。失败例不反驳已经保留全部前提的正确规则，也不把两字相邻解释成天然因果。

原始数据没有 `Born=true`、`Coord=true`、`Reach=true` 等答案字段。模式进入／退出来自成员与连接的前后比较；协调来自部件、连接、兼容性和信息判据；可达画像来自实际边集；任务动作则由协调和资源条件生成。规范判断由另行公开的示范标准计算，不属于事实 Formula。

## 运行及文件

```sh
python3 verify_rules.py
python3 verify_rules.py --check
```

首条命令重新生成四份 JSON。`--check` 重新计算并比较保存文件，不改文件；任一查询不符或保存结果不同都会报错。仅需 Python 3.9+ 标准库。引擎优先读取发布目录的 `../core/wenli.py`，工作目录下回退寻找原 10 号解释器；也可指定 `--engine /path/to/wenli.py`。本例没有修改 G1 核心。

若相邻存在 `../graph/typed_graph.json`（发布）或 `../v04_graph/typed_graph.json`（工作），运行时还自动检查 13 边到查询的绑定、模型归属、结果路径及缓存结果与本次重算的一致性。也可用 `--graph /path/to/typed_graph.json` 指定。此联检验证引用和实际结果，不自动证明中文解释与形式式语义相符。

| 文件 | 用途 |
|---|---|
| `raw_inputs.json` | 初始部件、资源、事件配方、基础边、表达记录及两套公开规范 |
| `models.json` | 三个完整 G1 模型及由事件算法生成的原始状态快照 |
| `transition_trace.json` | 每个世界事件的完整前后快照，以及模式进出、谱系增加、信息丢失、资源变化、协调结果 |
| `rule_results.json` | 13 条边、各主查询及辅助查询的请求、预期、实际结果、第二求值器结果和错误拒绝 |
| `verify_rules.py` | 原始机制、数据生成、G1 调用及关系运算交叉核对 |

稳定模型名是 `reorganization`、`constraints`、`expression_norms`。每条边主查询为 `edge_01.success`、`edge_01.counterexample`，依次至 `edge_13`。预期值只是验收要求，没有写入模型谓词表充当事实。

当前共有 48 个查询，均与另一个关系求值器一致；另核对 432 项原始事实与编译表的一致性、merge／operate 两个动作域的完整性，并验证 2 个错误类型输入被拒绝。第二求值器使用不同的关系复合／闭包算法并从原始快照取事实；两者共享公开的事件机制及部分事实判据。这是软件与模型的交叉核对，不是独立经验验证，更不证明普遍性或最小性。

## 一条完整的拆分—重组—任务轨迹

Entity 域固定为四个不同标识 A、B、C、D；部件域为 u、v。身份采用明示约定：拆分产生新的 B/C，合并产生新的 D。它们有谱系联系，但不相等。模式 `Org` 的条件是：实例当前活动，至少有两个部件，部件在连接图中连通。模式 `Unit` 的条件是活动且恰有一个部件。

协调 `Coord(i)` 是本例的有限结构判据：i 满足 Org，部件信息齐备，而且所需部件对兼容。它只表达这个声明的协调条件，不声称现实中任何任务成功，也不等于《中庸》的规范“和”。

| 状态／事件 | 原始变化 | 实际派生结果 |
|---|---|---|
| s0 | A 持有 u、v，二者连接；信息齐；资源 2 | E(Org,A) 真 |
| split：s0→s1 | A 退出活动集；B 持 u，C 持 v；拆连接；加谱系 A→B、A→C | E(Org,A) 由真变假；E(Unit,B/C) 由假变真；同一条边同时满足这些事件 |
| merge：s1→s2 | 部件齐、兼容且资源足够才执行；消耗 1；B/C 退出，D 持 u、v 并连接；加 B→D、C→D | E(Org,D) 真、Coord(D) 真，信息仍齐；D≠A |
| operate：s2→s_done | 在每个状态自动检查 Coord(D) 且资源≥1；满足才生成这条边；消耗 1 并增加任务完成记录 | Done 真 |

因此 `split;merge` 可得到一个与旧整体不同身份的新组织；`merge;operate` 可完成本例任务。结果来自实际中间状态匹配，不是图上的“分—合—生”自动给出。保留全部部件或外形也没有恢复 A 的身份。

三条失效支路把必要条件显露出来：

- `merge_lossy:s1→s3` 仍形成 D，却丢失部件 v 的信息。Org(D) 为真，Coord(D) 为假，因此自动生成器不开放 operate。合并不保证恢复信息或完成任务。
- `drain` 后资源为 0，部件仍兼容。`attempt_merge` 确实执行，结果 `s_empty_fail` 没有 D。结构允许与尝试发生不自动补足资源。
- `spoil` 后部件不兼容，资源仍为 2。`attempt_merge` 到 `s_bad_fail` 也不产生 D。资源足够不替代兼容条件。

`attempt_merge` 与效力动作 `merge` 分开：失败尝试有记录和后继；真正形成组织的 merge 在这些失败前态没有边。查询可行性时会说明所问的是哪一种动作，不把失败结果隐藏成成功。

另有 `cut_in_place`：仅切断 A 内部连接，保持原实例标识和部件归属。它改变组织结构，却没有创建 B/C，反驳“每次结构划分都必生新实例”。这不是把认识分类或词义划分当作物理动作。

## 势的画像来自可达关系，理的限制作用于边

`constraints` 的固定状态为 start、p、q、goal、harm。基础边中，start 可到 p 或 harm；p、q 互通，q 可到 goal。势在此严格取给定动作下的可达集合。

- 从 start 移到 p 会改变画像；从 p 移到 q 仍有相同可达集合。所以变化可能改变势，但并非每次变化都改变所选画像。
- `sync(move,allow_safe)` 删除进入 harm 的边；其闭包包含于原闭包，并仍可到 goal。
- 另一限制删除进入 goal 的边，从 start 便无法完成原目标。收紧约束不自动“更好”；需要另给目标或规范。
- 删除 goal 自环减少了边，却不改变任意有限可达关系，因为闭包本来包含零步。限制后的包含未必严格。

这些结论来自关系运算，不把可达集大小直接当作价值、物理势能或成功概率。

## 时中、未发与规范和分别处理

`N_timely` 是本例公开的时间规范：时窗关闭则禁止；时窗开放且任务有义务则要求；否则许可。它只评时间条件。s1 的 merge 既被要求又可执行；s1_late 的 merge 物理上可执行，但时间规范禁止；s1_empty 的 merge 被要求却不可执行。这里没有从可行性直接推出合宜，也没有从规范要求创造现实边。

`edge_13` 还将动作与保信息边约束取交集。正常 merge 的交集有边；lossy merge 的交集为空，尽管时间规范仍要求该动作。采用限制后必须重新检查非空性，不能用未经限制的动作替它提供可行性证据。动作名称和最终受限过程的绑定均保存在查询中。

`expression_norms` 单独处理 core.082.01 的“未发状态”与 core.083.02 的“发而中节评价”。n0 无表达记录，作为本例未发表征；它有真实候选表达路径到 n_fit 或 n_excess。公开的 `N_expression` 逐项检查表达类型与形式是否符合本情境允许表：例如 anger 的 reasoned_objection 被允许，insult 被禁止。这是一项现代示范标准，不是古典“中节”的唯一解释。

表达完成后，n_fit 在该规范下获 permitted，n_excess 获 forbidden；n0 仍为 undetermined。未发因此不保证所有后续表达都合节。`N_timely` 的许可也从未被翻译成规范和。两种规范表均不能作为 Formula 原子调用；这种类型错误有专门拒绝检查。

本例没有把中解释为数值中点、平均值、稳定点或控制目标区间，没有新增这些义项。

## 十三边的可执行登记

下表“失败检验”均说明无条件推论为何不成立；有条件规则的完整前提仍需保留。

| 边 | 正面检查 | 失败检验 |
|---|---|---|
| edge_01 生—变 | Born 的关系包含于同一 E 投影的 Change | A 的退出是变化，却不是 A 生起 |
| edge_02 变—势 | start→p 后 Reach 不同 | p→q 后 Reach 相同 |
| edge_03 势—理 | 限制边闭包不超出原闭包 | 删除目标边使目标不可达，限制不保证更好 |
| edge_04 分—合 | split;merge 产生新 D 与谱系，信息保留 | lossy 重组未恢复信息，也不恢复 A 身份 |
| edge_05 合—中 | merge 可行性与 N_timely 独立结合 | late 时能合而规范禁止 |
| edge_06 中—和 | 表达后依 N_expression 得到合节评价 | 同一个未发起点允许合节与失节两种后继 |
| edge_07 生—分 | 同一 split 边联合判定旧 Org 退出与 B/C 生起 | cut_in_place 未创建新实例 |
| edge_08 变—合 | merge 边改变部件归属 | lossy merge 未得到目标协调条件 |
| edge_09 势—中 | 动作可达性与时间评价结合 | 被要求但没有效力动作后继 |
| edge_10 理—和 | 条件齐备时受约束的 merge 尝试得到 Coord | 结构允许但资源不足时没有协调组织 |
| edge_11 生—合 | merge 使 D 进入 Org 模式 | 不兼容时尝试不产生 D |
| edge_12 合—势 | 正常 D 具备 operate→Done 路径 | 丢信息的 D 虽成组织却没有这条路径 |
| edge_13 中—理 | 规范与受结构约束后的非空动作结合 | 规范要求而关系交集为空 |

这组案例补齐的是登记与模型内推演。它没有证明这八字或十三边是唯一、最小、普遍或历史上已有的统一体系，也没有用测试次数代替这些证明。
