# 八卦动力学的有限模型验证

本案例固定八种爻位结构，再分别指定三条更新规则。**相同的八种结构可以支持保持、收敛、循环等不同历程；仅有卦的分类，还不能决定动态怎样发生。**全部更新律都是现代建模假设，验证结果是这些有限模型中的计算结论。

## 文件与运行

| 文件 | 内容 |
|---|---|
| [bagua_models.json](bagua_models.json) | 固定编码、规则定义和三个完整G1模型。 |
| [verify_bagua.py](verify_bagua.py) | 穷举变换，调用共享G1解释器，检查轨迹、持续条件与关系。 |
| [results.json](results.json) | 1488项断言的结果，含888次G1顶层命题求值，以及供可视化使用的全部边、轨迹、循环和分量。 |
| [abstraction_examples.py](abstraction_examples.py)与[模型](abstraction_examples.json) | 两个检验卦类抽象是否保留结论的有限反例。 |
| [abstraction_results.json](abstraction_results.json) | 反例另计49项断言、36次G1顶层命题求值，全部通过；不混入主计数。 |


## 编码与基本变换

三位向量统一写为`(b1,b2,b3)=(下,中,上)`，1表示阳、0表示阴。字符串左端是最低爻，不能按图上从上到下的顺序直接读取。

| 卦 | 编码 | C逐位取补 | R倒转爻位 |
|---|---|---|---|
| 乾 | 111 | 坤000 | 乾111 |
| 兑 | 110 | 艮001 | 巽011 |
| 离 | 101 | 坎010 | 离101 |
| 震 | 100 | 巽011 | 艮001 |
| 巽 | 011 | 震100 | 兑110 |
| 坎 | 010 | 离101 | 坎010 |
| 艮 | 001 | 兑110 | 震100 |
| 坤 | 000 | 乾111 | 坤000 |

每个状态可任选一个爻翻转，得到3个邻居，因此共有24条有向单爻边，对应12条无向边。每个状态的入度、出度均为3；24条边逐条核对只改变一个位置。

`C(b1,b2,b3)=(1−b1,1−b2,1−b3)`；`R(b1,b2,b3)=(b3,b2,b1)`。穷举确认`C²=R²=id`、`CR=RC`。R固定的自反卦是乾、离、坎、坤；C没有固定点。这些结论来自明确的位运算定义，不自动推出任何自然系统的作用机制。

## 六爻组合与互卦取中重组

六位结构按`下卦三位 + 上卦三位`排列，即从最低爻到最高爻的`(b1,…,b6)`。八种下卦与八种上卦产生64个互不重复的六位结构。

| 操作 | 定义 | 精确结果 |
|---|---|---|
| 交换上下卦S | `(b4,b5,b6,b1,b2,b3)` | S²=id；8个固定点，其余组成28个二环。 |
| 六爻倒序R6 | `(b6,b5,b4,b3,b2,b1)` | R6²=id；8个固定点，其余组成28个二环。 |
| 六爻取补C6 | `(1−b1,…,1−b6)` | C6²=id；没有固定点，组成32个二环。 |
| 取中重组H | `(b2,b3,b4,b3,b4,b5)` | 16个不同输出，每个输出恰有4个原像；不能求唯一逆。 |

交换上下卦不等于将六爻整体倒序。整体倒序还会将每个三爻结构的内部次序倒转。逐项验证`C6R6=R6C6`和`C6S=SC6`。

H丢弃b1、b6，所以：

```text
H(000000) = 000000
H(100001) = 000000
```

这两个不同输入具有相同输出，已经构成非可逆的反例。一般输出受`h2=h4、h3=h5`约束，仅剩四个自由位，故像有16种；每一像对应外侧两位的四种选择。

这里的“投影”仅能理解为选择坐标再重组。H通常不满足`H²=H`，不能称为数学上的幂等投影。例如：

```text
H(000100)  = 001010
H²(000100) = 010101
```

## 同一状态空间上的三条更新律

每次tick规定为同一固定时长`Δt=1`，单位可任意选定，但全程不变；更新规则也保持固定。因此无限步对应无界时间，不会因步长不断缩短而在有限时间内完成。测试、skip和闭包中的零步不计作tick。

| 规则 | 定义 | 循环与汇入结构 |
|---|---|---|
| identity | `F(b1,b2,b3)=(b1,b2,b3)` | 八个状态各自保持；八个固定点。 |
| zero | `F(b1,b2,b3)=(0,b1,b2)` | 全部状态至多三步到坤000；唯一固定点为坤，汇入它的起始状态有八个。 |
| negrotate | `F(b1,b2,b3)=(1−b3,b1,b2)` | 离与坎形成二环，其余六态形成六环；没有固定点。 |

negrotate的完整轨迹为：

```text
离101 → 坎010 → 离101

乾111 → 巽011 → 艮001 → 坤000 → 震100 → 兑110 → 乾111
```

直接代入得`F³=C`、`F⁶=id`。C没有固定点，所以周期不能为1或3；本例的周期只能是2或6，枚举分别找到上述两个环。

zero的三次更新恒为000，这是“至多三步”的根据；坤从第0步起已经在固定点。不能将这个人为规则的收敛结果解释成坤天然吸收所有现实过程。

## 可能变换与实际规则的路径

G1模型中保留两个不同层次：

- `one_line`：一次恰好翻转一爻的24条局部边。
- `potential=one_line*`：零次或任意有限次单爻翻转，能够连通任意两个状态，共64个前后态对。
- `tick`：按所选择的一条更新律实际允许的8条边。

`〈potential〉Is_乾`表示“允许一连串自行选择的单爻翻转时，存在到乾的路径”；`〈tick*〉Is_乾`表示“按这条固定规则反复更新时，可以到乾”。前者在八个起始状态都真，后者由规则决定。例如zero从坤只能留在坤，无法到乾；identity也不会从任何别卦到乾。

三条tick规则并不全是对单爻图的边作方向选择。identity有8条自环；zero和negrotate的部分步骤同时改变多个爻。把这种多爻tick画成单爻边，会改变这里规定的时间粒度和规则。

## Enabled MayLast与AllLast

为了使“允许继续”与“保持某个条件”可分别检验，另选一个演示持续域：

`K = 八态集合 − {坤000}`。

这是任意选定的测试约束，**没有把坤解释为坏、死或不应存在**。更换K会改变持续性结论。

```text
Enabled       = 〈tick〉true
MayLast_0     = K
MayLast_(n+1) = K ∧ 〈tick〉MayLast_n
AllLast_0     = K
AllLast_(n+1) = K ∧ Enabled ∧ [tick]AllLast_n
AllLast_∞     = [tick*](K ∧ Enabled)
```

MayLast_n说存在一条连续n步都满足K的路径；AllLast_n说所有允许路径都满足K，并在需要继续时有后继。AllLast_∞要求每个可达状态都满足K且没有死端。它不把box在空后继上的空真误作可持续。

这三条更新律均为确定、全定义函数，所以每态Enabled为真，且同一n的MayLast_n与AllLast_n相等。相等是这些模型的结果，不是所有分支模型中的恒等式。

| 规则 | 在演示K内可以一直运行的初态 |
|---|---|
| identity | 除坤以外的七态。 |
| zero | 无。每态最终进入被本次测试排除的坤。 |
| negrotate | 离、坎。其余六态的循环包含坤。 |

本程序对n=0至8逐态求值，并与直接生成的完整轨迹比较。有限K只有7态；若存在7步均留在K中的路径，路径已有8个状态位置，其中必有重复，由此形成可继续循环的路径。本例用这一界限另外核对有限检查与可达安全环的一致性。

将三个相同context_id、相同符号签名、不同tick解释的模型一起交给`assess`，AllLast_∞在坤为false，在其余七态为unknown。这表示三种明示规则假说给出不同答案；八态分类本身不足以决定采用哪条动力律。

## 闭合终端分量的含义

强连通分量指其中任意两态能够相互到达的最大集合；终端分量没有向外的tick边。程序还检查每个终端分量确有循环，不把孤立死端直接当作持续循环。

| 规则 | 全部强连通分量数 | 闭合终端分量 |
|---|---:|---|
| identity | 8 | 八个各自带自环的单态。 |
| zero | 8 | 仅坤这一带自环的单态；其他七个单态分量处于汇入途中。 |
| negrotate | 2 | 离坎二环与其余六态环。 |

这些是给定有限映射的循环类及其汇入集合。此处没有连续相空间、距离、邻域或扰动稳定性假设，因此不能仅凭“终端分量”就宣称已经得到连续动力系统意义的吸引子。

## 两个抽象反例

以下反例也由同一G1引擎实际求值，但单列计数；各原子步骤同样按固定`Δt=1`计。它们说明特定的结论转移失败，不是断言所有抽象都不可靠。具体状态与卦类状态使用不同context_id，通过显式映射β关联，不能直接当成同一个状态域。

### 聚合边可以制造不存在的长期路径

具体模型只有两条边：

```text
a → b       c → d
β(a)=β(d)=乾111
β(b)=β(c)=坤000
```

b与d均无后继。按“只要这一类中有一个代表存在该边，就加入类间边”的规则聚合，得到：

```text
乾111 ↔ 坤000
```

具体模型中任何起点都没有两步路径；卦类图中却能任意久循环。设K恒真，G1计算具体四态的`[step*](K∧〈step〉true)`全部为假，抽象两态全部为真。抽象的回程边由c提供，但沿a→b到达的是b，不能无条件将b换成同类的c继续。

程序同时验证所有具体边都有抽象像，而“对每一个具体代表，都能提升对应的抽象后继”不成立。仅有前一个条件不足以将抽象图的长期运行结论下传到具体对象。

### 每个原子关系都能提升仍不保证sync

令具体模型为：

```text
过程a：s → t
过程b：s → u
t ≠ u，且t、u都无后继
β(s)=A，β(t)=β(u)=B
```

A、B在本例分别代表乾与坤两类。抽象后两种过程都成为`A→B`。逐状态、逐原子过程检查可得：具体边的像存在；每个抽象后继都能从每个对应具体起点找到同类后继；K恒真也在映射前后保持。这些逐原子条件全部成立。

但sync要求**同一个具体前态和同一个具体后态**同时满足两条关系：

```text
具体：Ra ∩ Rb = ∅
抽象：β(Ra) ∩ β(Rb) = {(A,B)}
```

G1计算`〈sync(a,b)〉true`在具体s为假，在抽象A为真。t与u被合成同一个卦类，不会使它们变成同一个具体终点。因而一般有：

`β(Ra ∩ Rb) ⊆ β(Ra) ∩ β(Rb)`，本例是严格包含。

若要让含sync的结论在抽象前后保持，必须进一步检查共同终点能否联合提升；仅检查每个原子关系的提升不够。
